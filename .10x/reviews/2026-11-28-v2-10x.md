## 4. The columns (plan task 2 as extended by round 3 R11), after the eight names, all from the same hits and truth

| Column | Definition (ten words) | Source |
|---|---|---|
| `on_time_1500` | non-song-start occurrences shown within [−1 s, +1.5 s]: share | plan task 2; ADR-022 § 1 |
| `song_start_median_ms` | median signed delay of each song's first slide row | plan task 2 |
| `song_start_p95_ms` | nearest-rank p95 of the same song-start delays | plan task 2 |
| `wrong_per_10_songs` | gotos to neither current nor next truth slide, per 10 songs | plan task 2; spec § 2.2 |
| `hidden_mid_song` | unmatched blanks longer than 1 s while truth shows a slide | plan task 2; spec § 2.2 |
| `early_300` | occurrences shown more than 0.3 s before their truth row | round 3 (R11, SRE S2) |
| `early_1000` | same at 1.0 s; decoupled from the 1 s match window | round 3 (R11, SRE S2) |
| `tight_300` | non-song-start occurrences shown within ±300 ms: share | round 3; spec "Tight on time" |
| `wrong_slide_s` | seconds screen differs from truth, 50 ms steps, by slide id | round 3 (R11, ADR-031) |

- **The signed error** (shown − truth, ms, per matched occurrence) is the helper's per-row table, `Metrics.rows:
  Vec<(bool, Option<i64>)>` from `score::delays` (14 lines, `score.rs`): per truth slide row, (song start, the first
  goto to that slide between the neighbouring truth rows' times minus the row's time). It has no table column of its
  own: `median_ms` / `p95_ms` already summarise the matched ones, and the early counts, `tight_300`, `on_time_1500`
  and the song-start percentiles are its counts. **Decoupling:** a goto 1.2 s early is a false advance for the eight
  names (`EARLY_MS` unchanged) and −1,200 in the helper, so `early_1000` counts it; a 0.9 s early goto is a hit and an
  `early_300` (both pinned by tests).
- **No two columns measure the same thing.** `on_time_1500` (a one-sided 1.5 s bar with the 1 s early bound) and
  `tight_300` (±300 ms) are different windows; both names are the prompt's. The plan's `wrong_per_10_songs` is the
  spec's "wrong moves" without the early-hide clause (needs truth-v2 `last_ms`, V6).
- **Denominators (assumption, recorded):** `on_time_1500` and `tight_300` divide by the non-song-start truth
  **occurrences** (missed rows count against them), as ADR-022 § 1 and spec § 2.2 word it; the plan's task-2 line says
  "hits". With recall 1.00 on every committed fixture the two readings agree. With no non-song-start occurrence the
  share is 0/0 and prints `n/a`.
- **Song start:** the first slide row of each song, i.e. a slide row whose song differs from the previous slide row's
  (a reprise after a prayer in the same song is not one). Songs = song starts, for `wrong_per_10_songs`.
- **Wrong move:** a false-advance goto whose slide is neither the truth row owning its time (the eight names' span
  rule) nor the next slide row's; before the first row, only the next counts. A double advance is never a wrong move.
- **Hidden mid-song:** a false-advance blank (not a double) while the owning truth row is a slide row, inside the
  window [first truth row, last + 10 s], not lifted (goto or unblank) within 1 s.
- **Wrong-slide seconds:** at every 50 ms step of that window, the truth's last row versus `voxxad`'s screen (a goto
  shows, a blank blanks, an unblank re-shows the last slide, nothing shown at the start), compared by `Cue` (song and
  slide ids, or blank), steps × 50 ms. Early, late, wrong and blank in one number.
- Cell formats: shares and seconds with two decimals (`SHARES` in `score.rs`), counts and ms whole; `-` nothing to
  measure, `miss` a missed blank / unblank, `n/a` a share with nothing to count. `check()` reads only the eight
  `NAMES`; the nine `COLS` are reported, not gated; `fixtures/baseline.json` is unchanged.

## 6. The flags

- **`--actions <file.jsonl>` (plan task 3; did not exist; committed).** Scores an external list of `voxxad` stdout
  action lines against exactly one fixture dir's `truth.jsonl` (none or several is a usage error, exit 2). No
  `voxxad` run, no start-line mode check. A bad line is named by the actions file's path and its line number only
  (`tests/voxxa_eval_v2.rs::a_bad_action_line_names_the_file_and_the_line_number_only`: the placeholder words never
  appear). The baseline check runs as always (a dir without a baseline row is a report, exit 1, as for a private
  fixture). Prompt 07's `voxxa-eval --actions recordings\<date>-<slot>\actions.jsonl recordings\<date>-<slot>` is now
  the real syntax.
- **`--truth-from-screen <session.jsonl>` (task 7; built, 3 tests green, not committed, in the patch).**
  `score::parse_screen` reads only `t` and `slide` from a `trace` line of `kind: screen` (prefiltered by the substring
  `"kind":"screen"`, then checked); every other field is ignored, so V8c's field list (not yet in ADR-003 amendment
  1's table) can grow without touching the eval. **Assumption recorded:** `slide` is the global slide index, as
  `goto.global`, mapped to (song, slide) through the fixture's `setlist.json`; a settled re-report of the slide
  already shown collapses into one row; a screen truth has no blank rows; `t` going back is an error naming the
  line. `Metrics.operator_timed` makes `extra()` return `NaN` for the six timing columns (`on_time_1500`, the two
  song-start percentiles, `early_300`, `early_1000`, `tight_300`), printed `n/a`; the header carries
  `truth: operator-timed`; recall, wrong moves, hidden mid-song and `wrong_slide_s` are scored. On the made-up
  screen log (6 screen lines, one re-report, a `level` trace with extra fields) against the made-up actions:
  `5 5 5 0 1.00 1.00 … n/a n/a n/a 0.00 0 n/a n/a n/a 1.60`. Replaying a log that carries `trace` lines needs
  `Kind::Trace` in `events.rs` first (ADR-003 amendment 1 point 3; V3b), so until then the flag pairs with
  `--actions`, which is how the test runs it.
- **`--service-report <session.jsonl> [--truth <file>] [--out <dir>]` (task 6; built, 4 tests green, not committed,
  in the patch).** `report.rs` writes `service-<date>-<slot>.json` (date and slot from the log's name
  `session-YYYYMMDD-HHMM[-N].jsonl`, else from its start line's `log` name) with `version`, `model_sha256` (null:
  the start line carries a model file name, a string, not a hash), `backend` (null), `config_fnv1a` (FNV-1a over the
  start line's config), `setlist` (the fingerprint object), `hops` (one per `window` line: `t`, `s_per_pass`,
  `lag_ms`, `dropped` null), `levels` (null until `level` traces exist), `traces` (every trace line's number and
  boolean fields plus `kind`), `dispatch` (null until an action carries `t_sent`), `scored` (the eight names and the
  nine columns when `--truth` is given, its `setlist.json` beside it; the actions are the log's own `action` lines)
  and `slo` S1–S10 (S1 false_advances, S2 {early_300, early_1000}, S3 wrong_slide_s, S4 {recall, on_time_1500},
  S5–S10 null). `trend.csv` gets a header and one row per run: `date,slot,songs,occurrences,S1,S2,S3,S4,S5,…,S10,
  n_hold,hold_s,n_panic,n_next,n_back,songs_demoted` (S2 = `early_1000`, S4 = `on_time_1500` in the CSV; `slot`
