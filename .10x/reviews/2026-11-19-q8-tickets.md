## Q8-02 [low, adr] The strategy's red "Lyrics don't match what I hear" is not mapped
**What.** `blank_hold` shows amber ("Hearing talking, not a song. The screen stays blank."), because no existing signal tells a wrong setlist apart from a prayer or a sermon.
**Where.** `src/simple/logic.js:20`; ADR-017 § 2, "Not mapped".
**Why.** A church that loaded last week's songs sees amber all service, not red.
**Suggested fix.** From pilot data, decide a time-based rule, for example `blank_hold` for more than N minutes while the mic level shows music. Record it in an ADR-017 amendment, and test it in `tests/gui/simple_logic.test.mjs`.

## Q8-05 [low] `main.js`'s listening flag can drift from the backend
**What.** When the HTTP API starts or stops listening, `main.js`'s own `isListening` is not updated. The Simple switch follows the backend through polling, but its click goes through the old Listen button, which may then need two clicks. The switch's `pending` waits its 3 polls meanwhile. This is pre-existing.
**Where.** `src/main.js:694-708` (`toggleListening`); `src/simple/simple.js` (the switch).
**Why.** A volunteer may need two clicks on Off after a Stream Deck start.
**Suggested fix.** Let `main.js` take the running state from `get_status`, or from an event, when the HTTP API changes it (one or two lines in the GUI row). Add an e2e check: start through the mock's HTTP path, then Off stops it in one click.

## Q8-06 [low, security] The first-run model download checks no hash
**What.** The first-run model step calls `download_model`, which checks no checksum. This is the same path as the Models tab (#9).
**Where.** `src/simple/firstrun.js` (model step); `src-tauri/src/transcription/` (download).
**Why.** A changed or truncated file at the mutable URL would be loaded. The GUI cannot hash a file that the backend wrote without a new command, and Q8 allowed none.
**Suggested fix.** Fix it in the backend under #9, with the SHA-256 that `full-eval.yml` already pins for Tiny. When filing, link this ticket to #9, or file it as a comment on #9.

## Q8-10 [medium, privacy, tests] The set-up guide lets the shortcut keys through when the focus is on the page body (merge blocker)
**What.** The guide's key block sits on the overlay box only, so it catches only keys aimed inside it. `main.js`'s document listener still gets Space, S, B, N and P when the focus is on the page body. The focus is on the body when the guide opens on a fresh profile, and during the 20-second test after its Start button is removed. Verifier A, round 3, in the mock:
- (a) on a fresh profile, one Space calls `start_listening` under the guide;
- (b) with songs and a model loaded, Space on step 1 starts listening before a microphone is chosen (in the real app this opens the microphone behind the guide);
- (c) during the test, `s` opens the stage window, and Space stops listening, which gives the false verdict "I couldn't hear anything…".

ADR-017 § 1 (line 29) and Consequences (line 111) say the guide stops every key.
**Where.** `src/simple/firstrun.js:31` (the listener on `box`), `:174` (clears `#fr-extra`); `src/main.js:1563` (document keydown); `tests/gui/e2e.mjs:189`, `:326` (Space only on focused buttons).
**Why.** The microphone can open behind a dialog that has not yet asked which microphone to use, and the 20-second test can send the volunteer to the wrong fix (usability step U6).
**Suggested fix.** In `firstrun.js`, replace line 31 with a capture-phase listener: `window.addEventListener("keydown", (e) => { if (!box.hidden) e.stopPropagation(); }, true);`. A button's own Space and Enter, and a select's keys, still work. Optionally move the focus into the dialog in `go()`, and again after `run()` clears `#fr-extra`. Add e2e checks with the focus on `document.body`: on step 1, Space and `s` call neither `start_listening` nor `toggle_stage_display`; during the test, Space does not call `stop_listening` and the verdict is unchanged. Each check must fail on ee431ce. Cost: 1-2 lines in the Simple mode row (352 / 600). Then a verifier confirms. Keep ADR-017's wording once the code matches it.

## Q8-11 [low, tests] A text-only panel moved below Simple mode is not detected
**What.** Verifier B's mutant M6b appends `#privacy-card` to `body` after `#simple`, and it survives. The `onlySimple()` check flags only visible controls outside `#simple`, or elements whose box is on screen. `body` has `overflow: hidden` and `#simple` is `100vh` tall, so the card is off screen, yet a screen reader still reads it.
**Where.** `tests/gui/e2e.mjs:127-132`; `src/styles/main.css:21`; `src/simple/simple.css:6`.
**Why.** An accidental move of an Advanced panel out of `#app` would pass CI.
**Suggested fix.** Also flag any direct child of `body`, other than `#simple`, `#firstrun` and `#toast-container`, that passes `checkVisibility()`, wherever its box is.

## Q8-12 [low, documentation, adr, tests] The `machine-state` listener is redundant with the poll, and ADR-017 § 2 says otherwise
**What.** Verifier B's mutant M3c drops the `machine-state` listener, and it survives, because `refresh()` sets the state from `get_status.machine_state` every second. ADR-017 § 2 says the state comes from "the latest `machine-state` event; before any event, `get_status.machine_state`".
**Where.** `src/simple/simple.js:70`, `:102`; ADR-017 § 2, line 36.
**Why.** The ADR describes a priority that the code does not have. The event only shortens the delay.
**Suggested fix.** Reword ADR-017 § 2: the state comes from `get_status` every second, and the event is a faster update. Optionally add an e2e check that emits `machine-state` without changing the mock's state and expects the light within 300 ms.

## Q8-14 [low] Shortcut keys stay live in Simple mode outside its own buttons
**What.** With the focus on the page body in Simple mode, `main.js`'s shortcuts still act: Space toggles listening, S opens the stage window, B blanks, and the arrow keys send slides. Nothing in Simple mode shows it. ADR-017 Consequences records this as intended.
**Where.** `src/main.js:1563-1605`; `src/simple/simple.js:37`.
**Why.** A volunteer who presses a key in Simple mode can change what the audience sees, or open the stage window, without seeing a control.
**Suggested fix.** Decide in the founder's run (Q8-01) whether Simple mode keeps only Space, and record it in ADR-017. If the other keys go, a capture-phase listener in `src/simple/` can stop them while `#app` is hidden, and `main.js` stays unchanged.

## Q8-15 [low] The mode switch does not move with the arrow keys
**What.** The 10x switch uses buttons with `role=radio` and has no arrow-key handling, so the radio-group keys do not work. The ponytail lane's native radios did move with the arrow keys.
**Where.** `src/simple/simple.js` (the switch markup).
**Why.** Keyboard and screen-reader users expect the arrow keys to move a radio group.
**Suggested fix.** Add the arrow-key handling (roving `tabindex`), or use native radios. In the same pass, check contrast and target size against WCAG AA. The ponytail review measured 4.47:1 and a 12 px Advanced link on its own lane's CSS; nobody has measured `q8/base`.

## Q8-16 [low] Row 6 trusts each driver's `is_connected()`
**What.** Row 6 ("not found") fires only when `get_presenter_info.connected` is false. A network driver that still reports connected after its app closes falls through to green, until the first refused send turns row 5 red. Nobody has checked this per driver.
**Where.** `src/simple/logic.js:19`; the presenter drivers' `is_connected()` in `src-tauri/src/presenters/`.
**Why.** For a short time the light can be green while the presentation app is closed.
**Suggested fix.** For each network driver, check what `is_connected()` reports after the app closes, against the mocks. Record the result in ADR-017, and file a driver fix for any driver that reports connected.
