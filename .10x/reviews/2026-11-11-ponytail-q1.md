## Must fix

**1. PDF import makes one slide out of the whole file** (not in Q1 scope: hand to Q2)
- **What this is:** `importers/pdf.rs:24` splits the extracted text on the form-feed character (`\u{c}`) to get one slide per page. A form feed is the "page break" control character.
- **Problem:** pdf-extract never writes a form feed. I grepped both 0.8.2 and 0.12.1, and `PlainTextOutput::begin_page` writes nothing. A 5-page lyric PDF becomes one slide holding all 5 pages, so the conductor can never advance inside that song. docs/SETLIST_FORMATS.md:180 promises one slide per page. This bug was already in May's code, the bump did not cause it, and it is not one of the 12 audit items.
- **Fix:** Call `pdf_extract::extract_text_from_mem_by_pages(bytes)` (it exists in 0.12.1) and make one slide per non-empty page. Add a test with a 2-page PDF.
- **If we skip it:** Every PDF setlist loads, but it never advances past "slide 1".

## Should fix

**2. reqwest now trusts only its built-in certificate list, not the computer's**
- **What this is:** `Cargo.toml:47` uses reqwest's `rustls-tls` feature. That feature means the `webpki-roots` crate: a fixed copy of Mozilla's root certificates compiled into the app. Before, native-tls used the OS certificate store.
- **Problem:** Some church networks run a content filter that inspects HTTPS. Its own root certificate is installed in Windows' store. With bundled roots, the model download, Planning Center and Hymnary.org fail with "UnknownIssuer". The old build worked on the same network. The author recorded this as debt, but the fix is one word.
- **Fix:** Use `rustls-tls-native-roots` instead of `rustls-tls`. It is still rustls with no OpenSSL. `rustls-native-certs` is already in the lock file, and its licences are already allowed.
- **If we skip it:** On filtered networks, Voxxa cannot download a speech model, so it cannot listen at all.

**3. README says previews never leave the booth, but the code ships a "second screen" Stage Display**
- **What this is:** README.md:13 says "on the booth computer only". README.md:22 says "The operator previews ... are not sent to any output."
- **Problem:** The merged code says the opposite:
  - the Stage button title is "Open Stage Display on a second screen" (index.html:196)
  - `commands/mod.rs:897-899` describes it as for "worship leaders on a confidence monitor"
  - stage.css says it "lives on the band's confidence monitor"
  
  A11 asks the README to stop contradicting the code, and this is a licensing claim churches will rely on.
- **Fix:** Delete the sentence on line 22 that begins "The operator previews…", and drop "on the booth computer only" from line 13. Or say plainly that the optional Stage Display can sit on a confidence monitor, and that it is never the projector output.
- **If we skip it:** The public README makes a promise the product breaks the first time someone clicks "Stage".

**4. Copyrighted lyrics remain in a user-facing doc and in tests (ADR-007)**
- **What this is:** A9 cleaned `setlist.example.json` and the OpenLyrics example. The same contemporary songs remain elsewhere:
  - `docs/SETLIST_FORMATS.md:34-38` has three lines of "How Great Is Our God"
  - unit tests in `aligner/mod.rs:592-613`, `importers/txt.rs:106`, `importers/easyworship.rs:203` and `planning_center/mod.rs:274` quote "How Great Is Our God", "Way Maker" and "How Great Thou Art" (Hine's 1949 English text)
- **Problem:** ADR-007 says the repo ships no copyrighted lyrics. The docs example is almost word for word what Q0 rejected in the old `setlist.example.json`. The author noted it as debt.
- **Fix:** Swap in lines from the public-domain hymns now in `setlist.example.json` (Amazing Grace, Be Thou My Vision, It Is Well). The docs change has no code risk. In the tests only string data and title asserts change. The conductor's logic is not touched.
- **If we skip it:** The public GPL repo keeps distributing the text that ADR-007 and A9 were meant to remove.

**5. loc_budget.py does not count inline `<style>` and `<script>`, and its docstring says it does**
- **What this is:** `scripts/loc_budget.py:27` adds `report["stats"]["code"]`. In tokei, "blobs" are the embedded CSS/JS blocks inside an HTML file.
- **Problem:** I tested tokei 15 on an 18-line HTML file with 3 lines of inline CSS and 4 lines of inline JS. It reports `stats.code` 11, with the 7 embedded lines only in `blobs`. So inline code is not counted, although the docstring says "counted once, as part of that HTML file". There are no inline blocks today, so today's numbers are right. With 8 lines of GUI headroom, the next GUI change can move code inline and pass the gate silently.
- **Fix:** Add the blob counts: `report["stats"]["code"] + sum(b["code"] for b in report["stats"]["blobs"].values())`.
- **If we skip it:** The GUI budget, which "can only go down", can be bypassed without anyone noticing.

**6. The .pptx importer was changed for zip 9 and quick-xml 0.41 but has no test**
- **What this is:** `importers/pptx.rs` changed in three places: `name()` now returns a Result, the match was folded for clippy, and entity text now goes through `xml_text`. There is no unit test and no .pptx example.
- **Problem:** If zip 9's `name()` returns Err for normal entries, or the `a:p` guard misbehaves, every slide is skipped or merged, and nothing fails. OpenLyrics got a new test for the same change, but pptx did not.
- **Fix:** Add one unit test. It builds a 2-slide .pptx in memory with `zip::ZipWriter`, puts `<a:p><a:r><a:t>Tom &amp; Jerry</a:t></a:r></a:p>` in a slide, and asserts the slide count and the text `"Tom & Jerry"`.
