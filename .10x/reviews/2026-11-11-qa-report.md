# Q2 QA report: verification of the merged base (2026-11-11)

**Role:** QA Engineer, Phase 5 (Verification). **Base tested:** `claude/trusting-newton-v71ebu` @ 1568810 (the May branch merged per ADR-010). **Fixes:** branch `q2/10x`, 1568810..b09373d (24 commits), plus the state commit. **Companion files:** `2026-11-11-security-review.md`, `2026-11-11-q2-tickets.md`, `2026-11-11-ponytail-q2.md`.

## 1. Verdict

- **Before Q2 the merged base was not safe for a live service.** One dropped PDF aborted the app; five confirmed wrong-slide defects put the wrong content on the audience screen; every `listen()` call was rejected; capture needed a 16 kHz device that ordinary PCs do not have; a model download froze slide control; a broken model was listed as Downloaded.
- **After Q2 every crash, data-loss, freeze, listening-impossible and wrong-slide defect found is fixed, each with a test that fails without the fix.** That is 18 triaged fix-now items plus 1 wrong-slide defect the adversarial verifier found at the end (Q2-44). The remaining 34 items are tickets (14 medium, 20 low) (`2026-11-11-q2-tickets.md`).
- **Not yet proven on real hardware.** QA ran in simulate mode (user decision): no microphone, no live keystrokes, no real presentation app. The founder's manual checklist (§10) is the next gate before a pilot.

## 2. Scope and method

**Mode: simulate plus one real model download** (user decision, 2026-11-11). The safety rules were:
- Never open the microphone: `start_listening` and `/api/v1/listen/start` were never called. The audio device was only queried for its formats.
- Never send live keystrokes: the default Keystroke driver types into whatever window has focus. Before any dispatch the GUI was connected to a local mock (ProPresenter 7 REST at 127.0.0.1:18025, or FreeShow at 127.0.0.1:7592), and `get_presenter_info` was checked first.
- Network: a local allow-listing proxy passed only huggingface.co, hf.co and hymnary.org. Planning Center calls were refused at the proxy, so no bytes left the PC. One Hymnary lookup and one Whisper Tiny download were allowed.

**How the app was driven.**
- Build: `cargo build --features tauri/custom-protocol` with `additionalBrowserArgs: --remote-debugging-port=…` added to both windows in a scratch copy of `tauri.conf.json`. The `WEBVIEW2_ADDITIONAL_BROWSER_ARGUMENTS` variable is ignored because wry sets the arguments itself. The committed config was never changed.
- A Node CDP driver used `Runtime.evaluate` to click DOM controls, dispatch DOM drop and keydown events, and call `window.__TAURI__.core.invoke`. No OS input.
- Speech: three 16 kHz mono WAVs were synthesised locally with `System.Speech` (Amazing Grace v1 and v2, a prayer) and transcribed by Whisper Tiny plus the VAD and the conductor in a scratch test. Results: v1 gave Goto slide 0, v2 advanced to slide 1, the prayer gave Noop.
- Inputs: `examples/*` (3-file GUI drop), `setlist.example.json`, a mixed drop, a 20,000-song EasyWorship database, 30 generated edge files and 10 crafted PDFs.

**After the fixes** the same CDP method was rerun on scratch builds of the fixed tree. The script is now committed as `scripts/qa/cdp-smoke.mjs` with the mock `scripts/qa/mock_pro7.py`. The last run (verifier, at ec35aac) passed 24 of 24 checks.

**Q2-01 — A malformed PDF aborts the whole app; imports run on the UI thread** (critical, crash, audit 11).
- Repro: drop a one-page PDF whose content uses `/F9 18 Tf` while the resources define only `/F1`, or one with `/MediaBox [0 0 612]`. stderr: `panicked at pdf-extract-0.12.1/src/lib.rs:204` … `non-unwinding panic. aborting.`, exit 127. Mutation fuzz: 144 of 3,000 inputs panic at 11 sites.

**Q2-02 — Unmatched speech re-shows lyrics after a blank; continuous unmatched speech never blanks** (high, wrong slide, audit 1).

## 7. ADR-011: can the stage window default to an audience-facing output?

**Result: no. No ADR-011 violation.**
- `tauri.conf.json`: the stage window is created `visible: false`, with no x/y, monitor or fullscreen setting, 520×480, `alwaysOnTop`. There is no window-state plugin, so no position is remembered. Q2 added `focus: false` and `focusable: false`.
- It appears only on an operator action (Stage button, `S` key, tray item), at the OS default position on the primary display. Live on a 3-monitor PC (DISPLAY1 primary at 0,0; DISPLAY2 at 1920,-10; DISPLAY3 at 0,-1080) it opened at (34,57) on DISPLAY1.
- It can still reach an audience in three non-default cases: the projector is the Windows primary display; displays are in Duplicate mode (then the operator window is projected too); the operator drags it onto the output, where `alwaysOnTop` keeps it above the presentation app.

## 10. Manual checklist for the founder

These need a real microphone, a physical unplug or a real presentation app. Do them on the booth PC before any pilot service.

- **Before you start:** clear `%LOCALAPPDATA%\com.voxxa.app` (or the `voxxa.*` localStorage keys). The Q2 runs left a mock presenter config there (127.0.0.1:18025). `%APPDATA%\voxxa\models\ggml-tiny.bin` is a good Tiny model; keep it.
- **M1. Real mic (Q2-10).** Press Start on the booth laptop's mic. Expected: the level meter moves. Report any "offers no 32-bit float or 16-bit capture format" error.
- **M2. Failed start (Q2-11).** Pick a device that fails (or unplug it), press Start, then Start again with a good device. Expected: the second Start works.
- **M3. Singing with the band (Q2-20, Q2-47).** Sing a full verse over the band with no pauses. Do transcripts arrive during the verse? Do the lyrics ever blank mid-song?
- **M4. Keystroke toggle (Q2-03).** PowerPoint or ProPresenter in front, Keystroke driver, PD setlist. Sing verse 1: the screen must not go black on first detection. At the end of the song, the blank must black out, not bring lyrics back. Also: on a black screen, does one slide key only end the black (the dispatcher assumes so)?
- **M5. Own-window guard (Q2-04).** Click Blank in Voxxa with the Keystroke driver: expect the "focus your presentation app" toast and no loop. Open the Stage Display: the presentation app must keep the keyboard.
- **M6. Unplug.** Pull the USB mic mid-listen. Expected: "Audio capture lost" toast and Start re-armed. Then press Stop normally: no "capture lost" toast.
- **M7. Auto-detect.** Press Auto-detect once. Answer the Windows Firewall prompt with "Private networks only". Is ProPresenter found?
- **M8. pptx order (Q2-22).** Reorder slides in PowerPoint, save, import. Does the order match?
- **M9. Real presentation apps (Q2-05).** ProPresenter 7 REST, FreeShow, OpenLP, OpenSong: jump to song 2 and confirm which slide appears; check Blank/unblank. For ProPresenter 6/7 WS, confirm Blank does nothing (Q2-23). With a ProPresenter presentation named shorter than the setlist title, note that Voxxa blanks and asks you to select it (Q2-48).
- **M10. Displays (Q2-30).** With the projector attached in Extend mode, open the Stage Display: it must appear on the operator screen. Try Duplicate mode and note that every Voxxa window is projected.
- **M11. Tray.** Tray → Start/Stop, Blank, Stage. Each should work.
- **M12. Export.** Export a setlist (`.voxxa-set`), re-import it.
- **M13. Close and relaunch (Q2-25).** Close the main window while listening; relaunch: one Voxxa only, focused.
- **M14. Stream Deck / Companion (Q2-13).** Connect a real profile with the generated token; next, prev and blank must work. The token changes each time the API is turned on with a blank field (Q2-51).
