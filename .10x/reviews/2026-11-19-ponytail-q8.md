## 1. The task, in short
Make Simple mode the default view:
- a three-position mode switch: Off, Songs, and Songs + Scripture (disabled until Increment 4′);
- a status light with one plain sentence (grey, amber, green or red), built from `MachineState`, the listening state and the presenter connection;
- the current song and slide;
- a Call for help button.

Every existing panel moves behind one "Advanced" link, and nothing is deleted. The welcome overlay becomes the first-run flow: device, then presenter auto-detect, then model download, then a 20-second test. The GUI stays under budget and free of runtime dependencies, and no backend command changes. Exit: a volunteer sees three controls, everything else is one click away, and the research plan's usability script passes on the founder's machine.

User decisions (binding, 2026-11-18; handoff, "User decisions for Q8"):
1. One new budget row, "Simple mode (src/simple/*)", capped at 600 and subtracted from the GUI row. The GUI row stays at 3,000, and the existing panels must not grow. The row is a recorded deviation.
2. GUI testing two ways: (a) a browser with a mocked backend, the only place where Listen, the 20-second test and audio paths may run; (b) the real app as a guarded scratch build with its own identifier, where Listen, the test, the keystroke presenter, the stage window and the HTTP API are forbidden.
3. The founder's own usability run is not a merge gate. It becomes a founder checklist item and a Q8 ticket.
4. No backend command change and no new command. No panel deleted. The ADR is ADR-017.

## 3. Cross-reviews

### Review of the 10x lane (f8500e3..99fe481)
**Verdict: fix 1 and 2 first.** The reviewer re-ran `npm run build`, `test:gui` (6/6) and `test:gui:e2e` (77/77, twice), and wrote two throwaway CDP probes against the same mock.
- **Must-fix 1.** A double-click on Songs could leave Off unable to stop listening. The second click got "Already running", `main.js` set its own flag to off while the backend kept listening, and every later Off started listening again.
- **Must-fix 2.** The red sentence for a refused slide change threw away the backend's reason. For a keystroke church with Voxxa focused, it said "check that it is open", which is the wrong advice.
- **Should-fix 3.** `main.js`'s document-wide shortcuts fire through Simple mode's and the guide's buttons: Space on a focused Next started listening.
- **Should-fix 4.** Nothing reconnects the saved presentation app at the next launch, so the second Sunday silently drives arrow keys.
- **Nit 5.** The device step has no stale-step guard.
- **Strengths named:** a pure, fully tested light table built only from signals that exist in the backend; one listening path through the old Listen button; a small Advanced move that deletes before it adds; compatible `localStorage` keys; privacy kept (Call for help calls no command, and the test keeps counts only); a dependency-free e2e that checks the mock is not in the bundle.

### Review of the ponytail lane (f8500e3..bdc3348)
**Verdict: request changes; one must-fix and five should-fixes.**
- **Must-fix.** The same double-click re-entry bug. After it, the view showed grey "Off" while the backend still listened.
- **Should-fix:** shortcut keys through Simple mode's buttons; the generic red sentence for keystroke users; a 20-second test that can pass with no audio, because its "green seen" flag latches and the conductor's first tick can repeat the last session's state (`src-tauri/src/listen.rs:73`); a first-run overlay that is not a real modal dialog; a start-up reconnect without the password, which fails every launch for kinds that need one.
- **Nits:** contrast just under 4.5:1 and a 12 px Advanced link; dense one-line state code; unhandled rejections; three spec deviations that need sign-off (amber `blank_hold`, a generic presenter sentence, Skip counted as done); CI tests only `light()`.

## 4. The comparator's ruling
**Base: the 10x lane at 99fe481.** Both lanes meet the hard limits. The deciding points:
1. **Tests that catch regressions.** The 10x lane runs a 77-check browser test in CI on Windows, plus `node:test` on three OSes. The ponytail walkthrough is not in CI, and its own review says that with a delayed mock it would have caught the must-fix.
2. **The Advanced code is left alone.** 10x changes `main.js` by one line. Ponytail exports nine internals, which ties Simple mode to them.
3. **The light follows the backend.** 10x reads `get_status`, so it stays right when the HTTP API starts or stops listening. Ponytail reads `main.js`'s flag.
4. **Records exist.** ADR-017 was written first, before any code.

**Grafts from the ponytail lane** (all applied on `q8/base`):
1. Reconnect the saved presentation app at start, never the keystroke driver and never a form that needs a secret, and treat "connected to another kind than the one chosen" as row 6 red (fa87345).
2. Write the status text only when it changes, so a screen reader does not re-announce it every second (91c3fc2).
3. The 20-second test passes only on a `slide-advanced` event inside the window, with "refused" and "not recognised" fail sentences (9653f48).
4. A sentence in the test step that tells keystroke users to click into their presentation app (42f7121).

**Review fixes to apply:** must-fix 1 (one toggle at a time), must-fix 2 (keep the presenter-error reason), Space and Enter on Simple mode's buttons and every key inside the guide kept from `main.js` (both reviews), the device step's stale guard (nit 5), and ADR-017 updated to match.

**Disagreements, and how they were settled:**
1. **Red while Off.** Ponytail shows red for a disconnected presenter even when nothing runs; 10x stays grey and names the next step. Kept 10x: a red light at rest would prompt needless calls for help.
2. **A red row for a refused start.** Ponytail has one. Not grafted, because it needs `toggleListening`'s error string, which means exporting `main.js` internals. Ticket Q8-13.
3. **Default model.** Kept Tiny (the model the eval measures) over Base. Neither download checks a hash (#9).
4. **How the switch reaches the backend.** Kept 10x's click on `#listen-btn` with polling, because `main.js` stays intact.
5. **Arrow keys on the switch.** Ponytail's native radios move with the arrow keys; 10x's `role=radio` buttons do not. An accessibility nit for later (ticket Q8-15).
6. **Where the guide is re-opened.** Kept 10x's "Set-up guide" link in the Advanced header, visible without opening a tab.
7. **Agreed by both:** `blank_hold` is amber, and Call for help is a message because of Q7-08 (#102). The founder's run should still confirm the spec deviations (Q8-01).
8. **The `[hidden]` rule** is the same in both lanes. The founder should look through the old panels once (Q8-01).

**Round 2, on 57fafcb: did not pass.** Three findings:

## 9. Lessons for the next step
- **A key block on an element only sees keys aimed at that element.** A modal that must stop document-level shortcuts needs a capture-phase listener on `window`, and a test with the focus where a user's focus really is: on the body.
- **Test what a user can see, not what the DOM allows.** `element.click()` clicks hidden elements, and `checkVisibility()` ignores opacity and position. Two verifier rounds were spent on this.
- **A double-click is the normal case for a slow command.** Both lanes had the same re-entry bug, and only a mock with a delay found it. Give every mock command a configurable delay from the start.
- **Exporting internals is cheaper today and dearer later.** The comparator chose the lane that left `main.js` alone, at the cost of one polling loop.
