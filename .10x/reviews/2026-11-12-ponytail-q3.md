## 1. The task, in short

Add a second binary, `voxxad`, that runs Voxxa's listening pipeline headlessly over `voxxa_lib`. It prints one JSON object per line (`"v":1`, `"t"` in ms), writes every event to a 14-day session log, and `--replay` must reproduce the action lines byte for byte without running the recogniser. The GUI's audio loop must move into the library so the GUI and the CLI share one function. User decisions: a separate 600-line budget row for `voxxad`; the loop must fit the existing rows ("everything else" stays at 2,500, so net growth of at most 17 lines); no sockets; no GUI change.

## 3. Cross-reviews

### `ponytail-review` of the 10x lane (74f6bd2..7199195)
**Verdict: Ship.** No correctness, safety or GUI-behaviour problem found.

- Checked replay: exact, because the conductor reads `last_speech` only in `tick` and never reads `state_since`, and both clocks give whole milliseconds.

- **One should-fix:** `tests/voxxad_events.rs` held four raw NUL bytes and two raw line breaks inside string literals, so ripgrep (and the Grep tool) treated the file as binary and skipped it. Fix: write the escapes.
- Not checked: `--device`, whether `tauri build` bundles `voxxad`, Linux/macOS CI.

### 10x Senior Engineer review of the ponytail lane (74f6bd2..3550b05)
**Verdict: approve once the must-fix is done.**
- **Must-fix:** the lane's claim that deferring `on_speech` to the next tick is "equivalent" is wrong. `on_transcript` also writes `last_speech`, so the deferred speech time (one chunk earlier) moves `last_speech` backwards after every transcript. The lane's own fixture shows it (`session.jsonl:38`, `:120`, `:178`). With default settings, `inter_verse_silence` fired at 25.6 s instead of 25.8 s and the prayer blank at 38.8 s instead of 39.0 s. In the GUI the shift is smaller but a transition can still land one tick early, which breaks user decision (2). Fix: make `on_speech` monotonic.
- **Should-fix:** release packaging (tauri-cli picks up `src/bin` targets, so installers will probably ship `voxxad`); no test of the extracted loop itself; replay does not record or check the setlist or `SmartConfig`.
- **Nits:** `println!` panics on a closed pipe (exit 101); `t0` taken before the model load; conflicting flags silently ignored; fatal errors after the log opens never reach the log; no warning for keystroke without `--shadow`; session logs keep 14 days of transcripts in the roaming `%APPDATA%`.

## 4. The comparator's ruling

**Base: 10x.** Both lanes met every exit criterion. The deciding criterion was "zero GUI behaviour change":
1. **GUI behaviour.** The 10x GUI path keeps `on_speech` on every chunk with the same lock nesting and emit order. The ponytail lane changes speech timing (the must-fix above), which breaks a binding user decision.
2. **Replay determinism.** 10x routes every input through `Conductor::apply`, keeps input order in the log, and refuses a session recorded with another setlist. Ponytail does none of this.
3. **Budget.** 10x leaves 4 lines in "everything else"; ponytail leaves none. Ponytail's binary is leaner (354 vs 504), but 10x still has about 96 lines in its row for the grafts.
4. **Simplicity.** Ponytail is smaller. The 10x extra lines buy `--model`, `--log-dir`, float WAV input, the `sessions/` subfolder, the fingerprint and logged config, and a `t0` taken after the model loads.
5. **Tests.** 10x has 13 tests to ponytail's 4, including a direct test of the shared loop (the coverage the ponytail review said was missing), a replay test with all output lines removed, a mutated-transcript test and a refused-setlist test.
6. **ADR.** ADR-013 already existed in the 10x lane, written before the code.

### Round 3 (two independent verifiers at f2bcea1): **one pass, one fail**
**Verifier A: pass.** All 7 gates pass. It exercised every flag except `--device`; parsed every stdout line (keys in order `v`, `t`, `type`); checked session-log naming, same-minute suffixes and 14-day rotation (only `session-*.jsonl` names older than 14 days deleted); replayed five WAVs byte-identically, including a 32-bit float WAV and a 4-action service run; showed that two concurrent runs under heavy CPU load wrote byte-identical logs; confirmed shadow and `--presenter none` leave the mock's `/_log` empty; got exactly one error line and exit 1, with no panic, for 18 bad inputs (bad WAVs, models, setlists, session logs, presenters and flags). Minor notes, not failures: `--help` is plain text; under `--shadow` the start line shows `"presenter": null`; errors before the session file opens go to stdout only.

**Verifier B: fail.** All 7 gates pass, and a line-by-line comparison of the old GUI loop with `listen::run` plus the GUI sink found no GUI behaviour change. Of 13 mutations, 9 were caught and 4 survived every gate:
- **N9 (open, more serious):** deleting the shadow guard in `connect_presenter` (`src-tauri/src/bin/voxxad/main.rs:312-314`, `if args.shadow { return Ok(None); }`) makes `--shadow` connect and dispatch. No test reaches `connect_presenter` with `--shadow`; only the manual exit demo checks it. This guards the exit criterion "shadow dispatches nothing" and the safety rule that `--shadow --presenter keystroke` must not type. The verifier showed a model-free test is possible (`--model nonexistent` stops after the presenter is connected, so `--shadow` and non-shadow runs can be told apart). Ticket **Q3-01**.
- **N8b, N8c, N8d (open):** in the GUI sink in `commands::start_listening_with_state` (`src-tauri/src/commands/mod.rs`, about lines 187-205), negating `is_blank` in `machine-state`, dispatching with `operator=true`, or renaming `mic-level` all pass every gate. The code is correct today; the GUI event contract has no automated protection. Ticket **Q3-02**.
