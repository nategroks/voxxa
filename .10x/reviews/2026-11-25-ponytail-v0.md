## 4. Ponytail review of the V0 prompt (the strategy draft's plan, step V0, before the rulings)
What this change does: V0 makes Windows release builds compile whisper.cpp with `/O2` by setting two CMake variables, and guards them with a check on the CMake cache, a test and new cache keys. It also gives the founder a script for local builds. Load assumed: one founder cutting a few release tags, and CI on every PR.

**Must fix**
1. **The exit test needs a release nobody approved** (the plan's V0 exit, "passes on windows-latest and fails on a scratch branch")
   - **What this is:** the proof that the check works on GitHub's Windows runner.
   - **Problem:** `build.yml` runs only for a tag and always makes a draft release, and a new rc tag needs the founder. A lane cannot run it, on a scratch branch or anywhere else.
   - **Fix:** (ruling 1, done) the script gets a fixture test on every PR. The end-to-end proof moves to the next approved rc, and `status.md` holds it as a Pending item.
   - **If we skip it:** V0 can never meet its exit, or someone cuts a tag without approval.
2. **The local recipe can silently do nothing** (step 5)
   - **What this is:** the PowerShell script that sets the two flags for local builds.
   - **Problem:** the repo's habit is `powershell -ExecutionPolicy Bypass -File …` (`tap-truth.ps1`). That runs the script in a child process, so the variables are gone when it exits. The build then runs unoptimised with no error. Checked: after `-File`, the caller has neither variable.
   - **Fix:** (done) dot-source it in the build window after `Set-ExecutionPolicy -Scope Process Bypass`. The script and both docs say so, and the same check script verifies a local build.
   - **If we skip it:** local evals report numbers about 3.5 times too slow, and nobody notices.

**Should fix**

3. **A `$GITHUB_ENV` step in `ci.yml` and `full-eval.yml` does nothing** (step 1)
   - **What this is:** a Windows-only step to set the flags in CI.
   - **Problem:** both workflows build debug only. whisper-rs-sys then uses RelWithDebInfo, and `*_FLAGS_RELEASE` is never read.
   - **Fix:** (ruling 2, done) leave both alone. Their own missing `/O2` is V0-01.
   - **If we skip it:** dead, untested lines, and a false belief that the Windows CI evals run optimised.
4. **Changing every cache key is more than the bug needs** (step 2)
   - **What this is:** new rust-cache keys so that no unoptimised build is restored.
   - **Problem:** rust-cache v2.9.3 keys by job id and OS, so `build.yml:165` (job `build`, macOS/Linux) never reaches the Windows job, and the `ci.yml` and `full-eval.yml` keys hold debug builds. It also hashes every `CMAKE*` variable, so even the Windows key changes by itself.
   - **Fix:** (done) rename only the Windows key, so the change is visible and pinned by the test.
   - **If we skip it:** three caches start cold, with slower first runs, for no gain.
5. **The calibration asks the founder for what is already measured** (step 3)
   - **What this is:** comparing the flag lines of a broken and a fixed build.
   - **Problem:** the orchestrator's caches already show broken `-nologo -MD -Brepro -W0` and fixed `-MD -O2 -Ob2 -DNDEBUG`.
   - **Fix:** (done) those lines are the test's fixtures. No founder round trip and no `.vcxproj` fallback.
   - **If we skip it:** the step waits for a founder answer that changes nothing.

**Nice to have**

6. **The check script arrives with CRLF on windows-latest** (`build.yml`, the new step)
   - **What this is:** the runner's checkout of `scripts/ci/check-msvc-release-flags.sh`.
   - **Problem:** Windows runners check out with `core.autocrlf` true. A bash that rejects `\r` would fail the Windows release job with `$'\r': command not found`.
   - **Fix:** none needed here: Git Bash, which `shell: bash` uses on Windows, ran CRLF copies of both scripts correctly (4/4). If the rc shows the error, add `*.sh text eol=lf` to `.gitattributes`.
   - **If we skip it:** worst case, one rc run fails at the check and needs a re-run after the one-line fix.
7. **ADR-021's status says nothing about § 4, and some references leave the repo**
   - **What this is:** the ADR's status line and its pointers.
   - **Problem:** "Accepted § 1; §§ 2-3 Proposed" leaves § 4 (no whisper-rs bump) unstated. FA-23, ADR-022 and steps V3/V4 live only in the uncommitted strategy draft.
   - **Fix:** set § 4's status, and add the targets, when the strategy draft is committed.
   - **If we skip it:** a reader cannot tell whether the no-bump rule binds V3/V4.
