## 2. Assumptions and decisions (the user was absent)

1. **A song start** is a slide row whose previous truth row is not a slide of the same song: the first row, the row after a blank, a new song. Reason: after a blank the follower re-enters from silence exactly as at a song start, and the spec counts song performances; so a reprise after a prayer is a performance. Song performances = song starts, the divisor of `wrong_per_10_songs`.
2. **`on_time_1500` and `tight_300`** are shares of non-song-start **rows** (occurrences, missed ones included), as spec § 2.2 and FA-05 word it; the plan's "share of non-song-start hits" is read as the same thing (a missed occurrence is not on time). `-` when there is no such row (`prayer-before-first-song`: both rows are starts).
3. **The signed error** is the per-row list `delays` returns (`Metrics.signed` for the other rows, `Metrics.starts` for the starts), not a column: a per-occurrence list has no cell. Its summaries are the early counts, `tight_300`, `on_time_1500` and the song-start percentiles. `median_ms`/`p95_ms` stay the eight names' latencies under the 1 s match window.
4. **The helper's window** is from the previous truth row's time to the next row's: a move is "early" however early it is, down to the previous row; a goto two rows early is `None` for its row, as the eight names already call it a miss plus a false advance.
5. **`early_300` and `early_1000`** count every row, song starts included (a next song shown before the operator is an early move the SRE's S2 wants). Decoupled from `EARLY_MS`, which is unchanged: a 0.9 s early move is a hit and an `early_300`; a 1.5 s early move is a false advance, a miss, an `early_300` and an `early_1000` (tested).
6. **`wrong_per_10_songs`**: "the current truth row" is the last row (slide or blank) at or before the goto; "the next" is the next slide row after it (a blank row between is skipped: the spec says "occurrence"). "Skips of ≥ 2" are covered: a skip that lands on the next truth row is right, any other lands on neither. A double advance is not a wrong move.
7. **`hidden_mid_song`** is a `blank` action while the truth shows a slide, lasting over 1 s on the 50 ms grid; the screen's blank start before the first goto and a blank carried out of a truth blank into the next song are late starts, not hides; the truth's own blank ends a hide. **Shortcut** (`score.rs:178`): a blank after the last truth row is never a hide, since without a song-end row nobody knows whether the song was still going; read `song_end` when truth v2 lands (V6). The first build counted the blank start as a hide (six on the public fixtures); the review caught it (§ 3).
8. **`wrong_slide_s`** follows the prompt to the letter: every 50 ms step from the first truth row to 10 s after the last where the shown slide (by `Cue`, song and slide id; a blank screen counts as different) is not the truth's. The blank before the first goto counts; the 10 s tail counts.
9. **Column pairs:** `on_time_1500` and `tight_300` measure the same share with two windows; the prompt names both, so both stay. `wrong_per_10_songs` (a count per 10 performances) and `wrong_slide_s` (seconds) are different measures. No plan column was dropped.
10. **`V2` is one space-separated string** (`score.rs:208`), not an array: nine names as an array are eleven code lines of the row for the same information; the table and `v2()` zip `V2.split(' ')`.
11. **`--actions`**: the file replaces the `voxxad` run; the start-line mode check is skipped (a saved `--full` run has a start line); errors are prefixed with the file path and `parse_actions`'s line number; an `error` line is named by its number only (its message may quote heard words). Not refused: zero or several fixture dirs (the kit's prompt 07 shows the one-dir call; the result is a baseline failure, not a wrong number).
12. **`--truth-from-screen`**: `slide` on a `screen` line is the slide's index in the whole setlist (`global` on action lines), the one self-sufficient reading; V8c may add `song` or a within-song index, and the parser ignores every other field. The setlist is `setlist.json` beside the log (a fixture folder has it; a church copies the service's setlist next to the session log). The log's own action lines are the moves. `n/a` is printed for every name holding `ms`, `300`, `1500` or `early`, so the eight names' latency cells go `n/a` too (Correct bar only). No baseline check in this mode.
13. **Setlist reading:** `parse_screen` prefilters lines on the two JSON substrings `"type":"trace"` and `"kind":"screen"` before parsing (a text line holding both would be read and then named as a bad line, never scored).
14. **Lines given back:** `mode`, `stderr` and the error-line message of `main.rs` were rewritten into one-liners (−9 lines) to fit the cap; clippy refused the first `mode` form (`obfuscated_if_else`), the array index form stands.
15. **Docs:** `fixtures/README.md` documents the columns and flags although the scope list does not name it (the file defines every column). `kit/skills/voxxa-wav-intake/SKILL.md` is not touched (the layout spec names a V2 extension; the brief's scope says nothing more).
16. **Commits:** the Rust change is one commit (the three flags share `score.rs` and `main.rs`; splitting by hunk would leave trees that no gate ran on), prompt 07 another, the records a third.

## 3. Ponytail review of the change (ponytail-review, on my own diff)

**What this change does:** `voxxa-eval` keeps its eight baseline numbers and adds nine columns computed from the same truth rows and action lines: how early or late each slide came, how many moves were early, wrong or hid the lyrics, and how many seconds the wrong slide was on screen. It can also score a saved action file instead of running `voxxad`, and build the truth from a log's read-back `screen` lines when a church runs FreeShow. Load assumed: one person, one service log of about 90 minutes, a few thousand lines; the 50 ms walk is about 108,000 steps against a few hundred truth rows.

**Must fix**
1. **Hidden mid-song counted late starts** (`score.rs:168-187`, first build) — *What this is:* the screen walk counted every stretch where the screen was blank and the truth showed a slide. *Problem:* the screen starts blank and voxxa needs words before its first goto, so every song start and every song after a prayer counted as a hide: 6 on the six public fixtures, where the conductor never hid lyrics. *Fix (done):* a hide begins with a `blank` action while the truth shows a slide (`hid`, `:178`), the truth's blank ends it (`:182`); 0 on every fixture, the made-up cases in `hidden_mid_song_counts_blanks_over_1_s_that_start_while_a_slide_is_sung` pin both. *If skipped:* the Correct bar's "0 hidden mid-song" could never pass.
2. **An `error` line of an actions file was printed in full** (`main.rs:115-120`, first build) — *What this is:* the loop that reports `voxxad`'s `error` lines quoted the line unless the run was `--full`. *Problem:* `--actions` takes a saved `--full` run, whose error messages may hold heard words (ADR-019 § 7; prompt 07: "nobody opens or prints it"). *Fix (done):* `quiet = full || --actions` names the line number only; the test's `noisy.jsonl` case fails without it. *If skipped:* a word a volunteer sang could land in a terminal and a pasted ticket.

**Should fix**
3. **The service report is missing** (task 6) — *What this is:* `service-<date>-<slot>.json` and the `trend.csv` row V13s and V15 read. *Problem:* it does not fit the row (§ 6). *Fix:* none inside V2's cap; the comparator or the founder decides (the other lane's answer, a smaller report, or a row of its own through an ADR). *If skipped:* V13s computes its SLO table from the eval columns by hand until then.
4. **`--actions` with no fixture dir** (`main.rs:73-82`) — *What this is:* without a positional dir the eval scores every public fixture against the same actions file. *Problem:* nonsense numbers and `FAIL` lines, exit 1. *Fix:* three lines to refuse `dirs.len() != 1`; left out for the cap, the kit shows the one-dir call. *If skipped:* a mistyped command fails loudly, never silently.

**Nice to have**
5. **`want` is a scan per step** (`score.rs:175`) — a `rev().find` over the truth per 50 ms step: about 108,000 × 300 comparisons on a 90-minute service, under a second. A cursor would be two lines; not worth them.
6. **The screen prefilter** (`score.rs:454`) — two substring tests before `serde_json` on every line; the same shape as `parse_actions`'s skip, kept.

7. **The setlist was read after the truth** (`main.rs:91`, second build) — *What this is:* moving the setlist read into `songs()` put it in the argument list after `read(truth.jsonl)`. *Problem:* a fixture with a bad setlist and no truth file reported the missing truth, not the setlist, which `eval_numbers_only`'s `a_bad_setlist_is_named_by_line_and_column_not_quoted` pins (the full suite caught it; the eval-only run cannot). *Fix (done):* `let songs = songs(&setlist)?;` first, one line. *If skipped:* a church's first error message would point at the wrong file.

**Verdict:** Ship the three commits; fixes 1, 2 and 7 were made before the first commit. **Lean:** −0 lines possible inside the row at this budget; the record names the 50 the missing task needs. **Not checked:** CI on Linux and macOS (no OS-specific path in the change), the real `screen` field list (V8c has not merged).
