## 2. ADR-019 (as I would write it)

```markdown
# ADR-019: WorshipTools Presenter: found by process, keys only when Presenter is in front; MIDI deferred

**Status:** Accepted 2026-11-20 (founder answers D1, D2, D4, D5, D6 and Addenda 1–2; D3 dropped) · **Feature:** church-autoadvance · **Reversibility:** Easy (one key profile, one discovery source, one dispatch rule) · **Owner:** nategroks · **Amends:** ADR-006 (its review trigger fired; see Decision 10) · **Related:** ADR-007, ADR-011, ADR-015

## Context
- The first pilot, The Lighthouse (booth PC LHMEZPC01), runs WorshipTools Presenter. Presenter has no local API (ADR-006, A4). Its remote apps go through WorshipTools' cloud. It accepts MIDI In, which needs loopMIDI or rtpMIDI, and keyboard shortcuts. So the pilot's only app is Tier 3.
- Today Voxxa does not find Presenter: discovery only probes HTTP ports and mDNS. The Presenter key profile sends `.` to blank, which does nothing in Presenter (T4). The driver checks only that Voxxa's own window is not focused.
- Founder test card, LHMEZPC01 (`reviews/2026-11-20-worshiptools-founder-test.md`):
  - T1: the process is `Presenter`, `C:\Program Files\Presenter\Presenter.exe`, window "WorshipTools Presenter".
  - T2: Right on a song's last slide moves to the next service item.
  - T3: F10 clears the lyrics. How to bring them back was not tested.
  - T4: `.` does nothing.
  - T5: not applicable.
  - T6: the .mp4 is test audio only.
- Keystroke drivers step through the setlist by its global slide index (`dispatch.rs:141-160`). A Goto into another song presses Right or Left once for each slide in between. The conductor never moves past a song's last slide on its own: the tracker picks a slide inside the song, and a manual step is clamped. So Voxxa presses Right past a last slide only when the song changes.

## Decision
1. **Found by process (Windows only).** If `Presenter.exe` is running (T1), discovery returns kind `keystroke`, profile `worship_tools_presenter` and source `process`. There is no port and no network call. Other operating systems return nothing.
2. **Keys only when Presenter is in front.** With this profile, a key is sent only when the foreground window belongs to `Presenter.exe`. Otherwise nothing is sent, and the status light shows amber: "Bring WorshipTools Presenter to the front." The check for Voxxa's own window stays. Off Windows the check cannot run and passes (marked `shortcut:` in the code).
3. **Right is never sent past a song's last slide.** With this profile, a Goto into a different song presses no key. Voxxa records the new song's first slide as the position (where Presenter lands when the operator moves to the next item), and asks the operator to move Presenter on. Inside a song, stepping works as before. The operator's own raw Next/Prev key is the operator's choice and is not changed. A dispatch test proves the rule.
4. **Key map.** Right is next, Left is previous, and there is no blank key. F10 is the *candidate* blank key (T3). Until the founder confirms a key that brings the same slide back, the profile reports `can_blank: false`. A conductor blank is then skipped, and the light says Voxxa cannot clear Presenter's screen. An operator blank returns "not supported". F11, F12, Up, Down, numpad + and numpad − are never sent: they clear media or change the service item. A test pins the exact key map.
5. **MIDI deferred** (D2). It needs loopMIDI or rtpMIDI installed on the booth PC. It is the next step if keys prove unreliable.
6. **Video songs dropped** (Addendum 2: no video plays in services). The setlist gets no video field.
7. **Licensed media.**
   - The .mp4, and everything made from it (audio, setlist, truth, session logs), exists only on LHMEZPC01 under `fixtures/private/<name>/`, which git ignores. It never goes to Drive or anywhere else, and agents never open, copy or move it.
   - The repo refuses media. The root `.gitignore` ignores `*.mp4 *.mov *.m4v *.mkv *.webm *.wav *.flac *.mp3 *.m4a` and `fixtures/private/`. A test in `src-tauri/tests/` and a CI step fail on any tracked path with one of those extensions (in any case) or under `fixtures/private/`. They allow exactly the 15 public-domain WAVs already tracked in `src-tauri/tests/fixtures/voxxad/`, listed by name. History is not rewritten.
   - Each local eval run on a licensed song adds one row to `fixtures/LICENSED_RUNS.md`. The columns are date, title, artist, CCLI Song #, church CCLI License #, source, machine, Voxxa commit and the summary numbers. No lyrics, recognised words, AppData paths or media hashes go in it.
8. **#73 (Q5-01) closes as "local eval only".** A CCLI song cannot run in CI. CI keeps the committed public-domain stand-ins.
9. **Budget** (D5; a recorded deviation from ADR-010 Decision 3). One new row, "discovery (src/discovery/)", stops counting in "everything else", which stays at 2,500. Its cap is Q9W's measured count rounded up to the next 50. The detection and guard code goes in the presenters row.
10. **ADR-006's review trigger has fired, by founder decision.** The trigger is "> 25% of support tickets concern one Tier 2/3 app". No tickets exist yet, but the only pilot runs a Tier 3 app. ADR-006 stays Accepted and points here. Its "sends only when the target app is foreground" is now true for this profile only.

## Alternatives
| Alternative | Why not |
|---|---|
| MIDI now | Needs a driver installed on the booth PC; keys plus the guard work today (D2). |
| No foreground guard (as today) | Keys land in whatever window is in front, during a service. |
| Step across songs as the other profiles do | T2: the extra Right goes into the next service item, which may not be a song. |
| Ship F10 now, with unblank pressing F10 again | Unblank was not tested (T3); it may not bring the slide back. |
| After a song change, hold every key until the operator confirms the song in Voxxa | Simple mode has no song chip, so auto-advance would stop after the first song. |

## Consequences
Good: Presenter is found. Keys never go to the wrong window. A song change never skips into the next service item.
Bad:
- Voxxa is still blind. After a song change it assumes the operator moved Presenter to the next song. If not, the next Right inside the song moves Presenter into the next item.
- Voxxa cannot clear Presenter's screen until the T3 follow-up.
- If Presenter runs as administrator, Windows drops Voxxa's keys silently (UIPI). The founder checklist covers this.

## Review trigger
- The founder confirms an unblank key (then `can_blank` becomes true).
- A Sunday shows that keys are unreliable (then MIDI).
- WorshipTools ships a local API.
```

## 6. ponytail-audit of the plan

**What this plan does:** R0 rewrites Voxxa's prompt pack and records so the next two steps, Q9W and Q9V, make keystroke control safe for WorshipTools Presenter and add a licensed test fixture that stays on the church's PC. **Load assumed:** one booth PC, one operator, one service a week. Here a wrong key costs a visible mistake on the projector during a service, and a leaked lyric costs a licence problem.

### Must fix

1. **The app forgets the Presenter profile at every launch** (`src/simple/firstrun.js:75-79`, `src-tauri/src/lib.rs:80-87`)
   - **What this is:** At startup, Voxxa reconnects the presentation app the operator chose last time.
   - **Problem:** It skips the keystroke driver ("it is the default"), and the default profile is `Universal`. After the first restart, the Presenter guard, the song-change rule and `can_blank: false` are all gone, and Voxxa sends `.` and steps across songs again. Q9W as written does not mention this.
   - **Fix:** Reconnect a saved keystroke form whose profile is not `universal`. That is one condition on `:77`, plus a GUI test (now Q9W step 5).
   - **If we skip it:** The guard works in testing and is off on Sunday morning.

2. **"Never Right past the last slide" works, but only in dispatch, and Q9W did not say how** (`dispatch.rs:120-162`, `aligner/mod.rs:288-293, 431-449, 607-622`, `aligner/evidence/mod.rs:165-181`)
   - **What this is:** The conductor sends "go to song S, slide N". Keystroke dispatch turns that into Right or Left presses, using the difference in the setlist's global slide index.
   - **Problem:** The conductor never goes past a song's last slide by itself: the tracker only picks slides inside the song, and a manual step is clamped (`aligner/mod.rs:672`). The extra Rights come from a song change: a new song detected, or a song-chip jump. Dispatch presses one Right for every slide in between. Dispatch only sees `kind()` and `capabilities()`, not the profile. It also sets `sent.song` only in the goto branch (`:140`). So a conductor-side fix can't work, and a dispatch fix needs a per-driver flag. There is a limit no code can remove: Voxxa is blind. If the operator doesn't move Presenter, the next Right *inside* the new song still goes into the next item.
   - **Fix:** As in Q9W step 3: a flag the driver sets per profile; `sent.song` kept in the stepping branch; on a song change, no key, the new song's first slide recorded, and the existing "select …" message. Test it with a fake presenter. Leave the operator's raw Next (`commands/mod.rs` `manual_step` falls back to `dispatch::step` at a song's end) alone: that is the operator's choice. "Hold every key until the operator confirms" is not possible: Simple mode has no song chip.
   - **If we skip it:** Every song change can jump Presenter into announcements or a video item.

3. **`can_blank: false` is ignored everywhere** (`keystroke.rs:147-149, 202-205`, `dispatch.rs:45-62`, `src/simple/logic.js:16-19`)
   - **What this is:** Capabilities tell the rest of the app what a driver can do.
   - **Problem:** The keystroke driver reports `can_blank: true` for every profile, and dispatch never checks it. With blank set to `None`, every blank the conductor sends during a prayer fails with "operation not supported…". The light shows that red, as "didn't take the last slide change". Putting F10 in the code instead would be worse: unblank presses the blank key again.
   - **Fix:** Take `can_blank` from the key map. Dispatch skips a conductor blank when it is false, and an operator blank returns "not supported". When `can_blank` is false, the light's blank sentence says Voxxa cannot clear Presenter's screen (now Q9W step 4).
   - **If we skip it:** A red light at every prayer, and a light that says "the screen is blank" while the lyrics stay up.

4. **The ffmpeg route makes a fixture the eval cannot score** (`cli/voxxa-eval/main.rs:80-81`)
   - **What this is:** A fixture needs `audio.wav`, `setlist.json` and `truth.jsonl` (when each slide went up).
   - **Problem:** Q9V's ffmpeg command makes audio only. `voxxa-eval` then stops with exit 2, because `truth.jsonl` is missing. Only the recording kit times slide changes. The spec also uses three folder names (`see-a-victory-mp4`, `see-a-victory-live`, `see-a-victory`).
   - **Fix:** Make the kit the recommended route, with `-OutDir fixtures\private`. The ffmpeg route says "write truth.jsonl by hand". Use one folder: `fixtures/private/see-a-victory/`, as Addendum 1 says.
   - **If we skip it:** The founder makes the fixture, and the eval fails on the first run.

5. **`voxxa-eval --full` prints the words it heard** (`cli/voxxa-eval/main.rs:141, 146`, `score.rs:305`)
   - **What this is:** The eval runs `voxxad` with Whisper and scores its actions.
   - **Problem:** Three places print recognised words: `voxxad`'s stderr, which carries Whisper's log of the words it heard, goes straight to the console; an error prints `voxxad`'s whole stdout, hypothesis lines included; and a bad line is printed in full. With a CCLI song, the lyrics land on the console and in anything the founder pastes. Meanwhile, "accept a private fixture path" already works (`main.rs:54`).
   - **Fix:** In `--full`, set stderr to null. Errors name the exit code or the line number. Drop the "accept a path" half from Q9V.
   - **If we skip it:** The rule "print counts, never recognised text" is broken by the tool itself.

### Should fix

6. **No tool makes `setlist.json` from the church's `.txt`** (`importers/txt.rs:14`, `cli/voxxad/main.rs:192-196`)
   - **What this is:** Q9V says to import a `.txt` with Voxxa's txt importer.
   - **Problem:** That importer fills the GUI's setlist in memory. It writes no file, and `voxxad` reads JSON only. The obvious PowerShell 5.1 fix, `-Encoding utf8`, writes a BOM, and the JSON reader rejects the file (the kit's comment warns about this).
   - **Fix:** A BOM-free PowerShell snippet in the README (Q9V step 3). No code.
   - **If we skip it:** The founder is stuck at the setlist step.

7. **The media guard misses quoted paths and upper-case extensions**
   - **What this is:** A test and a CI step that run `git ls-files`.
   - **Problem:** With the default `core.quotePath`, git prints non-ASCII paths in quotes, such as `"fixtures/private/caf\303\251/audio.wav"`. The leading quote defeats `^fixtures/private/`, and the trailing quote defeats `\.wav$`. On Linux CI, `*.wav` in `.gitignore` does not match `X.WAV` either.
   - **Fix:** `git ls-files -z` (or `-c core.quotepath=off`), and lower-case the path before checking. Test the pure check with a fake list (Q9V step 1).
   - **If we skip it:** One accented folder name slips a licensed file past both guards.
