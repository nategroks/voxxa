## Q7-01 [low, security, tests] The zero-sockets test does not run on macOS
**What.** `tests/replay_no_sockets.rs` traces `voxxad --replay` with strace on Linux and ETW on Windows. On macOS it prints "skipped". DTrace (`dtruss`) needs SIP disabled, and hosted runners have it enabled.
**Where.** `src-tauri/tests/replay_no_sockets.rs` (`trace`).
**Why.** The replay code has no OS-specific branch, so the Linux and Windows runs cover the code. A macOS-only dependency that opened a socket at start-up would still go unnoticed.
**Suggested fix.** Look at a macOS mechanism that works without SIP changes, for example `DYLD_INSERT_LIBRARIES` with a small interposer counting `socket()` (our own unsigned binary allows it), or a sandbox profile (`sandbox-exec` with `(deny network*)`). Use it with the same positive control.

## Q7-02 [low, tooling] The report-only full eval has no trend and no notification
**What.** `.github/workflows/full-eval.yml` prints the table, adds it to the job summary and uploads an artifact. A metric that differs from the baseline gives only a `::warning::`. Nobody is told, and nothing compares a run with the previous one.
**Where.** `.github/workflows/full-eval.yml`.
**Why.** A Whisper or `whisper-rs` upgrade that changes what is heard on one OS would only be seen by someone reading the summary.
**Suggested fix.** When the founder starts running it on a schedule, add a step that diffs the table against the last artifact, and say in the runbook who reads it.

## Q7-03 [low, security, tooling] `ci.yml` pins its actions by tag, and one by a moving branch
**What.** `ci.yml` uses `actions/checkout@v4`, `swatinem/rust-cache@v2`, `actions/setup-node@v4`, `EmbarkStudios/cargo-deny-action@v2`, `taiki-e/install-action@v2` and `dtolnay/rust-toolchain@master`. The new `full-eval.yml` pins every action to a commit SHA.
**Where.** `.github/workflows/ci.yml`; `build.yml` is ticket Q2-28 (#10).
**Why.** A moved tag or branch runs new code in CI. The risk is limited: since Q7, `ci.yml` has `permissions: contents: read` and uses no secrets.
**Suggested fix.** Pin to SHAs with the tag in a comment, as in `full-eval.yml`. Let Dependabot (`github-actions` ecosystem) propose bumps.

## Q7-05 [low, security, privacy] Session logs get default file permissions
**What.** `open_session` creates logs with `OpenOptions::new().write(true).create_new(true)`, so on Linux and macOS they are created with mode 0666 minus the umask (usually 0644). Another local user who can traverse the folder can read the transcripts.
**Where.** `src-tauri/src/cli/voxxad/main.rs` (`open_session`).
**Why.** Logs hold prayers and names. Booth PCs are usually single-user, so this is low.
**Suggested fix.** On Unix use `std::os::unix::fs::OpenOptionsExt::mode(0o600)` and create the folder with 0700. Test it with a temp `--log-dir`.

## Q7-06 [low, tooling] tauri-cli bundles `src/bin/` entries regardless of features, and drops one by accident
**What.** tauri-cli 2.10.1's `get_binaries` adds every `src/bin/` entry not named by a `[[bin]]`. It also treats an entry with no source path as matching any path (`Path::ends_with("")`), so the second such entry is silently skipped. Q7 avoids both by keeping tools in `src/cli/`.
**Where.** Upstream `tauri-cli` `src/interface/rust.rs`. Ours: `src-tauri/tests/packaging.rs`.
**Why.** A future tool added to `src/bin/` would ship in the installers, and which one depends on the OS.
**Suggested fix.** Keep `packaging.rs`. Optionally report the `ends_with("")` behaviour upstream, with a two-binary reproduction.

## Q7-07 [low, security, tests] Shadow mode's "no network connection" is checked only locally
**What.** A full `voxxad --stdin-audio … --shadow --presenter propresenter7_rest …` run under ETW on Windows made no socket (security review §4.3). CI cannot repeat this, because a shadow run needs the Whisper model.
**Where.** `src-tauri/src/cli/voxxad/main.rs` (`connect_presenter`), and `shadow_never_connects_to_the_presenter` in `tests/voxxad_events.rs` (which checks with a listener, up to the model error).
**Why.** Shadow is the mode the docs tell churches to start with.
**Suggested fix.** Run the full-eval workflow's `--full` (which is `--shadow`) under the same tracer on Linux, as a report-only step, or extend `replay_no_sockets` to a shadow run when a model is present. The claim to check is "`--shadow` makes no network connection", not "no socket": on Linux and macOS tokio's signal driver (`tokio::signal::ctrl_c`, `main.rs:140`) creates one local AF_UNIX socketpair. So a strace check of `--shadow` must allow `socketpair(AF_UNIX, …)`, or filter for `socket(AF_INET|AF_INET6, …)` and `connect` calls only; the replay check (`trace=%network`, zero events) cannot be reused unchanged.

## Q7-08 [medium, privacy, security] The diagnostics report carries what the GUI heard
**What.** The listening loop logs every recognised transcript at Info level (`log::info!("Heard: {}", text)`, `src-tauri/src/listen.rs:182`). In the GUI that logger is the diagnostics ring buffer, and `generate_report` copies the buffer into the report (`recent_log`, `src-tauri/src/diagnostics/mod.rs:153`).
**Where.** `src-tauri/src/listen.rs:182`; `src-tauri/src/diagnostics/mod.rs:153`.
**Why.** An operator who sends a diagnostics report to support also sends prayer and announcement text, and names said from the front. Nothing tells them so. Q9's "Call for help" bundle (prompt pack) builds on this report, so the leak would grow.
**Suggested fix.** Log the transcript at debug level, or log only its word count at Info. Add a test that a report generated after a transcript does not contain the transcript's words (use placeholder words). Do this before any pilot leaves shadow mode (ponytail audit finding 3).

## Q7-09 [low, privacy] `voxxad --device` opens the microphone before it checks its inputs
**What.** With `--device`, audio starts (`src-tauri/src/cli/voxxad/main.rs:105-108`) before the presenter connects and the model loads (`main.rs:114-117`). With a missing model or an unreachable presenter, the microphone is on for a moment, and then `voxxad` exits with an error.
**Where.** `src-tauri/src/cli/voxxad/main.rs`, `run`.
**Why.** A microphone that switches on for a run that cannot work surprises the operator, and on some systems shows a recording indicator. It also makes a failed start look like a live one.
**Suggested fix.** Open the device last: connect the presenter and load the model first. A model-free test can check the order with `--stdin-audio` and a missing model (the presenter error must come before any audio is read). No microphone is needed to test it.

## Q7-10 [low, documentation] Companion "Path B" in INTEGRATIONS describes features nobody has checked
**What.** `docs/INTEGRATIONS.md:69-89` ("Path B — Bitfocus Companion") says Companion's Generic HTTP module can poll `/api/v1/state` and store JSON fields into `internal:` variables, and shows a feedback using `$(voxxa:voxxa_blank)`. **Where.** `docs/INTEGRATIONS.md:69-89`.
**Why.** A volunteer may follow steps for features their Companion does not have, and give up on Voxxa.

## Q7-11 [low, privacy, tooling] `voxxa-eval`'s "voxxad failed" error carries recognised words
**What.** When `voxxad` fails, `voxxa-eval` puts `voxxad`'s whole stdout into its error (`Err(format!("voxxad failed: {}", stdout.trim()))`, `src-tauri/src/cli/voxxa-eval/main.rs:146`). In `--full` mode that stdout holds `hypothesis` lines, so recognised words reach stderr.
**Where.** `src-tauri/src/cli/voxxa-eval/main.rs`, the `voxxad()` helper (lines 134-148).
**Why.** The full-eval workflow keeps these words out of the CI log only because its `grep '^voxxa-eval'` happens to drop the continuation lines. The runbook (`docs/runbooks/eval-regression.md` §5) tells the reader to act on this message, so the reader sees transcript text too.
**Suggested fix.** Put only `voxxad`'s error lines (or the last non-hypothesis line and the exit code) into the message. A test with a failing `voxxad` run whose stdout holds a placeholder hypothesis can check the words are not repeated.

## Q7-12 [low, tests] `fixtures/setlists/pd-hymns.json` and `fixtures/pco/plan-sample.json` fit no parser
**What.** `fixtures/setlists/pd-hymns.json` (`{v, songs:[{sections}]}`) cannot be loaded by `voxxad --setlist` or by any importer, and `fixtures/pco/plan-sample.json` is a digest, not Planning Center JSON:API. Both came from `local/windows-fixtures` (ADR-010 amendment A15) and have stayed unused since Q1.
**Where.** `fixtures/setlists/pd-hymns.json`, `fixtures/pco/plan-sample.json`; ADR-010 A15.
**Why.** Files that look like fixtures but load nowhere mislead contributors and cost review time. The eval's fixtures use the `voxxad --setlist` format instead.
**Suggested fix.** Convert each to a format the code reads and add a test that loads it, or delete it with a line in `fixtures/README.md`. Part of the lean cleanups the ponytail audit proposed (findings 11-14).
