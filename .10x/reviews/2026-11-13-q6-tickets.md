## Q6-01 [medium, gui, adr] The GUI stores the whole `SmartConfig`, so retuned `evidence` defaults never reach a user who has saved a setting
**What.** `saveSmartConfigSoon` (`src/main.js:1472-1492`) writes the whole `SmartConfig` to `localStorage` (`voxxa.smartConfig`). Since Q6 that includes the `evidence` block (ADR-016 Decision 7). On the next start, `loadSmartConfig` (`src/main.js:1421-1441`) lays the stored copy over `get_smart_config`'s defaults and pushes it back with `set_smart_config`. Once a user moves any of the four sliders, every later change to an `EvidenceConfig` default is ignored, without any message. The same is already true of the other fields the GUI does not show (`min_start_match`, `softmax_temperature` and the rest).
**Where.** `src/main.js:1421-1441` and `1472-1492`. ADR-016 Decision 7 and its second amendment, item 4.
**Why.** ADR-016's numbers were tuned on synthetic speech and must be re-tuned on real recordings (Q5-01). A retune shipped in an update would not reach the churches that already use the app.
**Suggested fix (a GUI change, so it needs the user's approval under Q6 user decision 5).** Store and restore only the four fields the GUI shows (`silence_to_blank_secs`, `unrecognized_speech_to_blank_secs`, `song_confidence_floor`, `min_song_dwell_secs`). On load, merge only those four from a stored object, so the backend defaults win for everything else, including `evidence`, and an old stored object with the whole config is cut down to the four fields. About 6 lines; GUI row 2,951 / 3,000. Test: a `gui_events`-style pure helper, or a note in the QA checklist.

## Q6-02 [low, tests] No test tells "every slide of a section is a section start" from the correct `is_start`
**Status: closed, not to be filed (2026-11-13).** The `is_start`-always-true mutant is now killed: with it, `evidence_is_kept_across_transcripts_with_decay` (`src-tauri/tests/conductor_evidence.rs`, added in 69795e4) fails, because its four-slide section then gives slide 3 the section prior and the move comes one transcript early. Re-checked on `q6/base` with the mutant applied by hand: `cargo test --test conductor_evidence` gives 18 passed, 1 failed (that test).
**What.** In the new test `a_chorus_of_two_slides_is_followed_through_both_and_on_to_the_next_verse` (`src-tauri/tests/conductor_evidence.rs`), the mutant that makes `is_start` (`src-tauri/src/aligner/evidence/sections.rs:65-67`) always true still passes. The second half of It Is Well's refrain is a subsequence of the first half, so both halves score the same, and the tie goes to the first half either way. Mutants that test the section's last slide, or that make `same_section` always false, fail the test.
**Where.** `src-tauri/tests/conductor_evidence.rs`; `src-tauri/src/aligner/evidence/sections.rs:65-67`.
**Why.** Under that mutant, the second slide of a multi-slide section gets the section or chorus prior (0.6 / 0.8) instead of 0.4. A jump into the middle of a chorus would then come one transcript sooner, and a wrong move there would be easier.
**Suggested fix.** Add a scripted case with a two-slide section whose slides do not share words. For example, take Be Thou My Vision from `fixtures/recordings/jump-be-thou-my-vision/setlist.json` with verses 2 and 3 labelled as one section. From verse 1, sing verse 3 one transcript at a time and assert how many transcripts the move takes. Then check that the mutant changes that count. This is not verified yet: find the transcript count where prior 0.4 and prior 0.6 differ first.
