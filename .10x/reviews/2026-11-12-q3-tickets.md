### Q3-01 (closed in 912b978; not filed) No test checked that `--shadow` builds no presenter
**What.** Deleting the shadow guard in `connect_presenter` makes `voxxad --shadow` connect to the presenter and dispatch every action, and every gate still passes (verifier mutation N9).
**Where.** `src-tauri/src/bin/voxxad/main.rs:312-314` (`if args.shadow { return Ok(None); }`); `src-tauri/tests/voxxad_events.rs` (the stderr test stops both runs on an 8 kHz WAV before a presenter is built).
**Why.** "Shadow dispatches nothing" is a Q3 exit criterion and a safety rule: `--shadow --presenter keystroke` must never type. Before 912b978, only the manual exit demo (the mock's `/_log`) checked it. **Closed:** `shadow_never_connects_to_the_presenter` in `voxxad_events.rs`; with the guard deleted the test fails.
**Suggested fix.** A model-free test: bind a `TcpListener` on 127.0.0.1 in the test, then run `CARGO_BIN_EXE_voxxad` with the 16 kHz fixture WAV, `--setlist`, `--presenter propresenter7_rest --host 127.0.0.1 --port <listener>`, `--shadow` and `--model nonexistent`. Assert the single stdout line is an error containing "unknown model" and the listener accepted no connection. Optionally run the same command without `--shadow` and assert that a connection was attempted. The presenter is connected before the model is picked, so the two runs differ without Whisper. Show that the N9 mutation fails the new test.

## Q3-02 [medium, tests] The GUI's listening event adapter has no automated test
**What.** Three mutations in the GUI sink survive every gate: `machine-state` sent with `is_blank` negated (N8b), the loop's actions dispatched with `operator=true` (N8c), and the `mic-level` event renamed (N8d).
**Where.** The sink closure in `commands::start_listening_with_state`, `src-tauri/src/commands/mod.rs` (about lines 187-205).
**Why.** The code is correct today: a line-by-line review against 74f6bd2 found no change. But Q3 rewrote the GUI contract (event names, payloads and dispatch arguments), and nothing would catch a regression. `operator=true` matters: in `dispatch::drive` it changes the presentation check on a song change, so the blank on an unconfirmed song change could be skipped. The old loop had no test for this either. **Deferred by the orchestrator on 2026-11-12; it does not block the Q3 merge. Reasons: verifier B's line-by-line review found the GUI sink behaves exactly as the loop at 74f6bd2; the old loop had no such test either, so Q3 lost no protection; it is not a Q3 exit criterion; and a pure mapping needs more than the 4 lines left in "everything else", so it would mean reworking verified GUI listening code just before the merge. Q4 rewrites `listen.rs` and this sink for the streaming hop, so Q4 owns this test.**
**Suggested fix.** Make the mapping pure and test it. For example, add `pub fn gui_event(e: &Event) -> Option<(&'static str, serde_json::Value)>`, used by the sink, with a test in `src-tauri/tests/` that checks the event name and payload JSON for State, Mic, Detection and Heard, and that `Input` and `Error` map to `None`. Keep `dispatch(&app, action, total, false)` in a one-line arm, or pin `operator=false` in a test. "Everything else in src-tauri/src" has 4 lines left (2,496/2,500), so make room by simplifying code in the same bucket. Do not raise the budget.

## Q3-03 [medium, tooling, adr] Release packaging: check whether `tauri build` puts `voxxad` in the installers
**What.** Earlier records called this Q3-T1. Cargo builds every `src/bin` target, and tauri-cli treats them as extra binaries, so the installers (MSI/NSIS, deb, AppImage, `.app`) will probably carry `voxxad.exe`. Nobody has checked.
**Where.** `src-tauri/src/bin/voxxad/`, `src-tauri/Cargo.toml` (`default-run = "voxxa"`), `src-tauri/tauri.conf.json` (bundle targets "all"), `.github/workflows/build.yml` (tauri-action); ADR-013 Risks.
**Why.** A second executable changes macOS signing and notarisation, the Flatpak manifest and what support can expect to find installed. ADR-013 says Q3 does not ship `voxxad` to churches.
**Suggested fix.** Run `tauri build --no-bundle` locally or check the CI build job's artifacts. If `voxxad` is included, add `[[bin]] name = "voxxad"` with `required-features = ["cli"]` (off by default; CI and `cargo test` pass `--features cli`) or a bundler exclusion. Q5 decides whether to ship and sign it (with the Companion docs).

## Q3-04 [medium, security, documentation] `voxxad --presenter keystroke` has no focus guard
**What.** `voxxad` has no window, so the GUI's own-window focus guard cannot apply. Without `--shadow`, keystrokes go to whatever window has focus, the terminal running `voxxad` included.
**Where.** `src-tauri/src/bin/voxxad/main.rs` (dispatch through `dispatch::drive` with `voxxa_focused=false`); ADR-013 Risks.
**Why.** A keystroke typed into the wrong window can run a command in the terminal or edit a document. The current mitigations are: `none` is the default presenter, `--shadow` and `none` build no presenter, and one stderr warning is printed (23c459c).
**Suggested fix.** Q5 docs (README and INTEGRATIONS) must say "focus the presentation app". In code, refuse a keystroke while the foreground window is the console that started `voxxad` (Windows: compare `GetForegroundWindow()` with `GetConsoleWindow()`), with a test of the pure check. Count it in the voxxad row (531/600).

## Q3-05 [medium, privacy, documentation] Session logs keep 14 days of full transcripts in the roaming `%APPDATA%`
**What.** Every `hypothesis` line, prayers and spoken names included, is kept for 14 days in `<data dir>/voxxa/sessions/`. On Windows `dirs::data_dir()` is the roaming `%APPDATA%`, which roaming profiles copy to the server on a domain-joined church network.
**Where.** `src-tauri/src/bin/voxxad/main.rs` (session file and rotation); ADR-013 Consequences (Negative).
**Why.** Voxxa never uploads the logs, but they do not necessarily stay on the machine. The diagnostics ring buffer, by contrast, keeps only recent lines in memory (see Q2-15).
**Suggested fix.** Q5's privacy text must say this and how to change it (`--log-dir`). Decide in an ADR note whether to move the default to `dirs::data_local_dir()` (`%LOCALAPPDATA%`, which never roams), at the cost of a second Voxxa folder.

## Q3-06 [medium, performance] Transcription runs synchronously inside the shared loop
**What.** Whisper runs inside `listen::run`, so ticks, timers and VAD stall while it works. This is a Q0 finding, unchanged by Q3. In a debug build `--realtime` fell behind (a 47 s file ended at t = 92,414 ms), and its timing differed from file speed.
**Where.** `src-tauri/src/listen.rs:140` (the 5 s batch, `accumulated.len() < 16000 * 5`) and the recogniser call after it.
**Why.** At a service the recogniser has to keep up with the room; a stalled loop delays blanks and advances. Related: Q2-55 (no guard when Whisper is slower than real time).
**Suggested fix.** Q4 replaces the 5 s batch with the streaming hop in this function. Measure `--realtime` in a release build first, and record real-time factor and tick lag as Q4 numbers.

## Q3-08 [low] The conductor repeats a goto to the slide already shown
**What.** On one run the action stream shows goto Amazing Grace/0 at 8.1 s and again at 17.6 s (verifier A, a 4-action service WAV). The 10x lane's `--realtime` run also made one extra goto to slide 0.
**Where.** `src-tauri/src/aligner/mod.rs` (`on_transcript`); `voxxad` action lines.
**Why.** Dispatch drops the repeat (`Sent`), so the screen is unaffected, but Q4's `voxxa-eval` reads action lines and would count it as an action.
**Suggested fix.** Decide in Q4 whether the conductor suppresses a goto to the current slide or the eval ignores it, and pin the choice with a test.

## Q3-09 [low, adr] The GUI writes no session log, and operator inputs cannot be replayed
**What.** Only `voxxad` writes session logs. Manual steps, song jumps and external blanks are not `Input` variants, so a GUI session could not be replayed even if it were logged.
**Where.** `src-tauri/src/aligner/mod.rs` (`Input`), `src-tauri/src/commands/mod.rs`, `src-tauri/src/bin/voxxad/events.rs`.
**Why.** ADR-003 promises "every problem is reproducible with `voxxad --replay`". Today that holds for `voxxad` runs only.
**Suggested fix.** When a GUI session log is wanted, add operator `Input` variants and schema types (ADR-001 allows 8; 6 are used), reuse the `voxxad` recorder, and record the decision in an ADR-013 amendment.

## Q3-10 [low] WAV input must already be 16 kHz mono; there is no `--language`
**What.** `voxxad --stdin-audio` accepts only 16 kHz mono 16-bit PCM or 32-bit float WAV, and does not resample. Language is always auto-detected.
**Where.** `src-tauri/src/bin/voxxad/main.rs` (WAV reader, model setup).
**Why.** Real recordings are usually 44.1 or 48 kHz stereo, so each needs converting first. That matters for Q4's eval corpus.
**Suggested fix.** Reuse `audio::Resampler` for other rates and downmix stereo, or document the `ffmpeg -ar 16000 -ac 1` step in the Q5 docs. Add `--language` if the eval needs it.

## Q3-12 [low, tooling] No gate catches control bytes in text files
**What.** Four raw NUL bytes inside a string literal made `tests/voxxad_events.rs` look binary, so ripgrep and the Grep tool silently skipped it (fixed in 7cc75b2). A vertical tab also got into `.10x/handoff.md` (fixed in 2a31aa6). Text written through a Bash heredoc on the Windows PC can turn `\0`, `\n` and `\v` into control bytes.
**Where.** `.github/workflows/ci.yml`; the local gate list.
**Why.** A file that tools skip hides tests from every future agent that searches the repo.
**Suggested fix.** Add a CI step (and gate 8 locally) that fails if `git grep -lIP '[\x00\x0b]'` finds a text file. The `-I` flag skips binary files such as icons and WAVs.
