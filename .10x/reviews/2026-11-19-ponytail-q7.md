## 7. Verifier rounds

**Round 1, on 86b549d: did not pass.**
- **Gate 4 was flaky on Windows.** One run failed `replay_opens_no_socket` with a single Winsock-AFD event charged to a replay. The test matched events by pid alone, over a system-wide trace with no time window, so a pid that Windows reused before or after the child, or an AFD event logged in a borrowed process context, counted against the replay.
- **A green CI log never showed which tracer ran.** The `traced with` line is printed by a passing test, and CI runs without `--nocapture`. A Linux runner that refused `unshare -rn` would have passed quietly with networking enabled.

**Fixes (aa16e90, records in 6386f6b).**
- The ETW session also enables `Microsoft-Windows-Kernel-Process` (start and exit). A child is charged only with socket-create (1000) and connect (1017, 1018, 1020, 1021) events that carry its pid and fall between its own start and exit events. A child without a recorded start or exit fails the test.
- `VOXXA_REQUIRE_NETNS=1` (set in `ci.yml` on Linux) fails the test when `unshare -rn` does not work. With `VOXXA_REQUIRE_SOCKET_TRACE=1`, a green Linux job now means strace inside `unshare -rn`, and a green Windows job means ETW.
- Three new unit tests run on every OS. Removing the time window or the event filter makes `etw_charges_a_replay_only_with_its_own_sockets` fail.
- Re-proved: 4 of 4 full `cargo test --features cli` runs pass (210 passed, 1 ignored); the replay TCP-connect mutant fails with 4 socket/connect events (ids 1000, 1000, 1018, 1017); a pass under process churn (39 short-lived `curl.exe` processes connecting during the test); the determinism mutant fails; the NSIS exclusion holds. QA report and security review §10.

## 9. Lessons for the next step
- **Check a graft against the toolchain before taking it.** Ponytail's `option_env!` guard looked right and never fired on cargo 1.99.1; the finisher found it only because a stale binary passed a test it should have failed.
- **A test of "nothing happened" needs a positive control and a required-tracer switch.** Both lanes built a control; the verifier still found that a green log could hide a weaker tracer. Every "zero" test should fail when it cannot prove what it watched.
- **Attribute system-wide trace events by time as well as by id.** Process ids are reused; a trace that outlives a child must bound each child's events by its own lifetime.
- **Two lanes on one 4-core PC double every timing.** Measured times in Q7 (38 min for a full eval, against about 12 min idle in Q6) are upper bounds, not budgets.
