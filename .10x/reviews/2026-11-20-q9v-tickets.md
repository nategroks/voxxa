## Q9V-01 [medium, security] Song text copied out of `fixtures/private/` passes both media checks
**What.** The media guard refuses audio and video files by extension, and anything under `fixtures/private/`. A text file holding a licensed song's words outside that folder passes both checks: for example a private `setlist.json` copied into `fixtures/recordings/<name>/` to try a replay, or a `slides.txt` saved next to the README by mistake.
**Where.** `src-tauri/tests/media_guard.rs:48` (`refused()`); `.github/workflows/ci.yml:157-199` (job `media`); ADR-019 § 8. 10x lane's risks; security record, Q9V.
**Why.** The GitHub repo is public. The founder's rule is that the media, the audio and the lyrics are never committed. Today only review and ADR-007's title test stand between a copied setlist and a public commit.
**Suggested fix.** Cheap partial guards, in the test and the CI job together: refuse any tracked `slides.txt`; refuse any tracked `setlist.json` whose song title is "See a Victory" or that is not under the public fixture folders listed in `fixtures/SOURCES.md`. Keep README step 9 (`git status` before committing). A general lyrics detector is out of scope.

## Q9V-02 [low, tooling] Make "media guard" a required status check on `main`
**What.** The `media` job fails a PR that adds media, but nothing forces a PR to wait for it. A PR can also edit `ci.yml` and `media_guard.rs` together and weaken both.
**Where.** GitHub branch protection for `main` (repository settings); `.github/workflows/ci.yml:157`.
**Why.** ADR-019 § 8 wants a PR that adds media to go red even if the test is skipped. A red job that is not required can still be merged.
**Suggested fix.** Founder: in the repository settings, make "media guard" a required status check on `main` (with the other CI jobs), and review any PR that touches `ci.yml` or `media_guard.rs`. Note it in ADR-019.

## Q9V-03 [low, tests] No test notices the media job being switched off with `if:`
**What.** `the_ci_step_passes_the_real_tree_and_names_every_planted_file` fails when the `media` job has `continue-on-error`, but an `if:` on the job (`if: github.event_name == 'push'`, which skips it on PRs) or on its step (`if: false`) passes every test. Verifier B, round 2: both mutants survived.
**Where.** `src-tauri/tests/media_guard.rs:202` (`media_job()`) and `:261`.
**Why.** It is the same neutering as `continue-on-error`, by another route.
**Suggested fix.** In that test, also assert that no line of the job is an `if:` key, for example `assert!(!job.lines().any(|l| l.trim_start().starts_with("if:")), ...)`.

## Q9V-04 [low, tests] The accent test catches a missing `-z` only while git quotes paths
**What.** `tracked_paths_are_read_as_written_even_with_accents` proves the `-z` parsing because git's default `core.quotepath=true` quotes an accented path. On a machine whose git config sets `core.quotepath=false`, a `tracked()` without `-z` would pass locally. CI uses the default and catches it. Verifier B, round 2.
**Where.** `src-tauri/tests/media_guard.rs:65` (`git()`), `:85` (`tracked()`), `:114`.
**Why.** A developer's own git config could hide a regression from the local run.
**Suggested fix.** Pass `-c core.quotepath=true` in `git()` (or only in `tracked()`), so the test behaves the same on every machine.

## Q9V-05 [low, security] The media guard matches file names, not content
**What.** Audio renamed to `.bin` or `.txt`, or a type outside the nine extensions (`.ogg .opus .aac .wma .aiff .avi .wmv`), passes both checks. The nine are the founder's list in ADR-019 § 8.
**Where.** `src-tauri/tests/media_guard.rs` (the extension list) and `.github/workflows/ci.yml:190` (the `case` patterns); `.gitignore:29-41`. 10x lane's risks; security record, Q9V.
**Why.** A careless rename, or a different export format from Presenter or ffmpeg, would slip past.
**Suggested fix.** Add the common other types to both lists and to `.gitignore` together (an ADR-019 amendment, since § 8 names the nine). Optionally refuse tracked files that start with a RIFF/WAVE, ftyp, ID3, fLaC or OggS header, outside the 15 allowed paths.

## Q9V-06 [low, privacy] A `--full` run that is killed leaves its session log in `%TEMP%`
**What.** `voxxa-eval --full` writes `voxxad`'s session log (every word heard) to a temporary folder that is deleted when the run ends. If the run is killed (Ctrl+C, a closed window, a crash), the folder stays in `%TEMP%`.
**Where.** `src-tauri/src/cli/voxxa-eval/main.rs:185` (`tempfile::tempdir()` in `run_full`). 10x lane's risks; security record, Q9V.
**Why.** On LHMEZPC01, a private run's recognised words would then sit in the user's temp folder until Windows cleans it.
**Suggested fix.** Give the temporary folder a fixed prefix (`voxxa-eval-`) and remove leftovers with that prefix at the start of each `--full` run; mention it in README step 7. Count it in the voxxa-eval row (488 / 600).

## Q9V-07 [low, privacy] Nothing in code refuses `--record` on a private fixture
**What.** `voxxa-eval --full --record fixtures/private/see-a-victory` would save the session log, with every word heard, as `session.jsonl` in the private folder. Git ignores the folder and the guard refuses it, so it cannot be committed, but the words then stay on disk. Only README step 7 and M17 say not to do it.
**Where.** `src-tauri/src/cli/voxxa-eval/main.rs:47` (`--record`), `:57`, `:190`; `fixtures/README.md` step 7. 10x lane's risks.
**Why.** A founder repeating a command from the public-fixture section could add `--record` by habit.
**Suggested fix.** Refuse `--record` (exit 2, "--record is for public fixtures only") when a fixture path has a `private` component. A few lines in the voxxa-eval row, with a test in `tests/voxxa_eval.rs`.

## Q9V-08 [low] In `--full`, a `voxxad` setup error shows only its exit code
**What.** In `--full` every `voxxad` failure reads "voxxad failed with exit code: 1": a missing Whisper model, a missing `audio.wav`, or a WAV that is not 16 kHz mono 16-bit. These errors come before `voxxad` hears anything, so their text holds no heard words, but it is hidden too.
**Where.** `src-tauri/src/cli/voxxa-eval/main.rs:167`; README steps 6 and 7. Ponytail review should-fix 2 (option (b), the README line, was grafted in ddb96b8; option (a) is this ticket).
**Why.** The founder, running M17 alone, has to work out the cause from README steps 6 and 7.
**Suggested fix.** In `--full`, when `voxxad` fails and its stdout has no `"state":"start"` line yet, show the error event's `message`. Extend `eval_numbers_only` with a failure before the start line (placeholder message) and keep the after-start failure number-only. Fits the voxxa-eval row.

## Q9V-09 [low, security] A tracked path with a newline can add a line to the CI log
**What.** The `media` job prints each refused path in `::error::… $path`. A path that contains a newline would print its second part as a new log line, which GitHub reads as a workflow command if it starts with `::`. It happens only for a path the job already refuses, so the job is red anyway.
**Where.** `.github/workflows/ci.yml:194`. 10x lane's risks.
**Why.** Low impact, but a crafted PR could add an annotation or mask text in its own failing run.
**Suggested fix.** Replace control characters before printing, for example `printf '::error::… %q\n' "$path"`, and add one planted newline path to the CI-step test.
