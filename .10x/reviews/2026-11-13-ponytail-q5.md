# Ponytail lane — Q5 (2026-11-13)

Independent pass, as the user asked (process rule, 2026-11-11). Q5 is a code step, so it ran the two-lane pattern used in Q1 to Q4:
- **Two build lanes** worked from the same base (3af8a1a) in worktrees that could not see each other's code: the **10x lane** (`q5/10x`, `C:/dev/q5-10x`) and the **ponytail lane** (`q5/ponytail`, `C:/dev/q5-pony`).
- **Cross-reviews** of each lane.
- **Comparator:** read both diffs and both reviews, picked the base, the grafts and the review fixes to apply.
- **Finisher:** merged the base into `q5/base` and applied the grafts and fixes, one commit each.
- **Adversarial verifiers:** re-ran every gate, ran Whisper Tiny on the rebuilt fixture audio and mutated the code. Three rounds.

**Outcome:** base = **ponytail lane**, with seven grafts from the 10x lane and the ponytail review's fixes. Verifier rounds 1 and 2 found surviving mutants and two gate gaps; each was fixed in new commits with a test that fails without the fix. **Round 3 at c10e963 did not pass:** verifier A passed, verifier B failed on six mutants that survive every test (two of them matter; §6). **The Q5 PR must not be merged until those are closed and re-verified** (§7). `q5/10x` (b6650a2) and `q5/ponytail` (c9da97c) stay local for reference, not pushed.

All song text in this record is from the public-domain hymn Amazing Grace. The prayer is synthetic speech written for Q2.

## 1. The task, in short
Add `voxxa-eval`: a fixture is `audio.wav` + `setlist.json` + `truth.jsonl` (`{t_ms, song, slide}` from the operator). It runs `voxxad --stdin-audio --shadow`, aligns the actions to truth and reports precision, recall, median and p95 latency, false advances per set, double advances, and blank/unblank timing. Add `fixtures/README.md`, `fixtures/SOURCES.md`, and a CI job that fails below `fixtures/baseline.json`. Exit: the eval table prints, and the CI gate is proven on a deliberately broken threshold.

User decisions (2026-11-13): two stand-in fixtures built from the committed public-domain WAVs, rebuilt reproducibly (no new audio committed); a CI gate that replays committed Whisper Tiny session logs (no model, no audio in CI), with a local full mode that can re-record them; one new budget row, "voxxa-eval (src/bin/voxxa-eval*)", capped at 600; no GUI change, no conductor change, no sockets.

## 4. The comparator's ruling
**Base: the ponytail lane at c9da97c.** Both lanes met every exit criterion and passed all 7 gates. Ponytail won on:
1. **Every named metric has a real number, and each fixture tests what it claims.** `prayer-then-reprise` measures the blank after a pause (200 ms), the unblank on the reprise (1,500 ms) and the Q4-04 late advance (8,900 ms); `prayer-without-pause` measures the Q4-03 no-pause blank (6,600 ms). Recall is 1.00 on both, so the baseline does not bake a known defect into the floor. The 10x lane's `per_set` thresholds had to allow recall 0.5 and one missed slide on every fixture.
2. **A stronger gate:** one threshold row per fixture (blank 500 ms on one fixture, 7,000 ms on the other); a missing row, an unknown metric, or `-`/`miss` against a threshold all fail.
3. **Budget headroom:** 452/600 against 593/600; the 10x row could not absorb its own review fixes or the grafts.
4. **Simpler:** fewer flags, a shorter scorer, a plain screen-state doubles rule, and no "already showing" rule (the rule that hid the unmeasured blank).
5. Both truth formats are easy to write by hand.

What ponytail lacked became grafts from 10x: the ADR and state files, range checks on truth rows, log-path hygiene, `shell: bash`, and the README's recording steps.

## 5. Disagreements and how they were settled
1. **Match tolerance, 750 ms (10x) or 1,000 ms (ponytail).** **1,000.** Both are defensible for an operator's reaction time; changing it would mean re-deriving the baseline for no gain.
2. **Truth blank syntax, `{"kind":"blank"}` or `{"blank":true}`.** **Ponytail's.** As easy to write, and it rejects `blank:false`; "room for future kinds" is weak for a one-bit row.
3. **The "already showing" rule.** **Not grafted:** the 10x review showed it hides an unmeasured blank.
4. **Baseline shape, uniform `per_set` or per-fixture rows.** **Per-fixture:** tighter limits per service shape, and a missing row fails. The cost is one row per new fixture, documented.
5. **Separate missed-blank and false-blank metrics.** **Not grafted:** `miss` fails `blank_ms`, and a blank during singing is a false advance.
6. **Precision denominator.** **Ponytail's** (hits ÷ all gotos, so doubles lower it), stated exactly in ADR-015 Decision 6 and the README.
7. **Match window: fix the documentation or the code?** **The documentation.** `[t − E, next − E)` is the shape the 10x lane chose on purpose; it keeps an early advance for row i+1 from being scored as a late hit for row i.
8. **`--current-config`.** **Documented now, built in Q6** (Q5-07); beyond Q5's exit criteria.
9. **The CI step duplicates `cargo test`.** **Kept**, with the comment and `shell: bash`: the real-CI gate proof and the visible table rely on it.
10. **Verifier gap: a dropped threshold switched its gate off** (round 1). **Closed in code** (ae3249f): a metric with a value and no threshold fails; ADR-015 Decision 8 amended at Q5 close.
11. **Verifier gap: a replay that ran Whisper passed locally** (round 1). **Closed in code** (0b7df6d): `voxxa-eval` exits 2 when `voxxad`'s `start` status line does not match the mode it asked for. CI (no model) would have failed anyway; the check makes a local run honest too.
12. **The broken `status.md` commit** (round 2 fixes). 1b0cc5d committed an empty `.10x/status.md` (an edit script opened the file for writing, then failed on a cp1252 encoding error, and a `&&` chain still committed). **Not rewritten** (new commits only): c10e963 restores the file from 624acad and adds the intended line; the net diff on `status.md` across both commits is one line. Whoever merges may squash the PR; nothing else needs doing.
13. **Merge after round 3.** Verifier B failed. **Not merged.** The open items are recorded as Q5-08 … Q5-10 and listed in §7.
