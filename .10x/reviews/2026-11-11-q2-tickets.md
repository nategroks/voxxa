No critical or high item is a ticket; those were fixed in Q2 (see `2026-11-11-qa-report.md` §6). File and line references are to `q2/10x` @ b09373d unless they say 1568810.

## Q2-14 [medium, security] HTTP API: Off or a token change does not close open keep-alive connections
**Problem.** `http_api::stop()` aborts only the accept loop. axum 0.7 serves each connection in its own task with the context it was accepted with, so an idle keep-alive keeps being served after the operator turns the API off, and keeps the old token after a restart with a new one. Since Q2-13 every request still passes the Origin/Host guard and the old token check, so only an already-authorised client is affected.
**Repro.** Start the API; open a keep-alive connection with the token (Python `http.client`) and GET `/api/v1/state`; turn the API off (or on with a new token); send again on the same connection → 200 with the old token. At 1568810 it was still 200 35 s later.
**Proposed fix.** Put `live: Arc<AtomicBool>` in the API context; `stop()` clears it; the guard returns 503 when it is false; add `with_graceful_shutdown`. Test: guard returns 503 with `live=false`; integration test: keep-alive, stop, send again → 503 or closed.
**Source.** Security review S2 (lane: High; refutation: Medium).

## Q2-15 [medium, privacy] Transcripts are kept in the diagnostic report (500 lines against the 2-minute limit)
**Problem.** `commands/mod.rs` logs every transcript at Info ("Heard: …") into the 500-line ring buffer, which `generate_diagnostic_report` exports and the docs suggest pasting into a GitHub issue. Sermons and prayers name third parties and reveal health and religion. The strategy's support-bundle control allows the last 2 minutes, shown before sending.
**Repro.** Listen through a prayer, then Settings → Diagnostic report: `recent_log` holds "Heard: …" lines for the whole service.
**Proposed fix.** Replace the line with a `log_transcript()` helper that logs `debug!("Heard {} chars", len)`. If support needs the text, keep a separate 2-minute in-memory buffer shown in the report modal. Test: log a canary sentence, generate the report, assert it is absent.
**Source.** Security review S4 (lane: High; refutation: Medium), QA.

## Q2-20 [medium] VAD has no maximum segment length; continuous singing may give no transcript
**Problem.** `vad/mod.rs` emits a segment only after 300 ms of silence while speech is confirmed, with no length cap; before confirmation, silent frames do not clear the buffer. Over a band with no pauses, the conductor may hear nothing for a whole verse (audit 14).
**Repro.** Feed 30 s of continuous voiced audio with no 300 ms gap: no segment until the end. Founder check M3.
**Proposed fix.** Emit the buffer at ~5 s; reset `speech_samples` on a silent frame while not in speech. **Promote to fix-now if M3 shows no transcripts during a sung verse.**
**Source.** Q0 audit 14, QA.

## Q2-21 [medium, security] No size caps on imports (pptx zip amplification)
**Problem.** `importers/pptx.rs` reads each zip entry with `read_to_string` and no bound; the GUI base64-encodes whole files. A 65,433-byte pptx produced a 67 MB slide; GB entries would exhaust memory (inferred). `catch_unwind` (Q2-01) cannot catch a stack overflow or abort inside pdf-extract.
**Repro.** Import a crafted `.pptx` whose `slide1.xml` inflates to GBs.
**Proposed fix.** Reject entries with `size() > 8 MiB` and read through `.take(8 MiB)`; skip non-slide entries; reject payloads over ~64 MiB before decoding. Consider a nesting limit or a worker process for PDF.
**Source.** Security review S5, QA.

## Q2-23 [medium, wrong-slide] ProPresenter 6/7 WebSocket driver cannot blank; lyrics stay up
**Problem.** `propresenter7_ws.rs` declares `can_blank: false`, so `blank()` returns Unsupported and the dispatcher only logs it. The screen keeps the last lyric slide after the song (as without Voxxa), while the operator may believe it blanked.
**Repro.** Connect Pro7 WS, sing, stop; the conductor emits Blank; the screen keeps the slide.
**Proposed fix.** Show "this driver cannot blank the screen; blank manually" at connect, and keep the conductor's blank state in sync with dispatch success. Implement `clearText` over the Pro6/7 remote protocol once a real ProPresenter is available.
**Source.** QA.

## Q2-24 [medium] After a restart Voxxa drives the Keystroke driver while Settings shows the saved network presenter
**Problem.** `lib.rs` always pre-connects Keystroke at startup. The GUI restores the presenter form, then `showPresenterConfigFor` overwrites the restored port with the default (1025/5506). The only status line is inside Settings, not on Home.
**Repro.** Connect ProPresenter 7 REST on a non-default port; quit or crash; relaunch: Settings shows ProPresenter with port 1025; `get_presenter_info` says keystroke.
**Proposed fix.** On startup, if the saved form names a network driver, auto-connect it (no secrets); on failure show "Not connected", not Keystroke. Apply the restored values after `showPresenterConfigFor`. Show the active driver on Home.
**Source.** QA (QA: High; adjudicated Medium: the likely outcome is no advance, and keys into Voxxa are refused since Q2-04).

## Q2-26 [medium, security] CSP is null and `withGlobalTauri` is true
**Problem.** `tauri.conf.json` sets `csp: null` and `withGlobalTauri: true`. Injected inline script runs and could call every app command from either window, including the view-only stage window. No injection sink was found (all untrusted text goes through `textContent`/`escapeHtml`), so this is defence in depth.
**Repro.** Debug build with CDP: inject an inline script that calls `window.__TAURI__.core.invoke('get_presenter_info')`.
**Proposed fix.** CSP `default-src 'self'; script-src 'self'; style-src 'self' 'unsafe-inline'; img-src 'self' data: blob:; connect-src ipc: http://ipc.localhost`. Later, an app manifest that limits the stage window to read-only commands. Behaviour change: none expected; check the GUI under the CSP with the CDP smoke.
**Source.** Security review S6.

## Q2-27 [medium, security] Model download: no checksum, mutable URL, no timeout
**Problem.** Models come from `huggingface.co/.../resolve/main/<file>` with `reqwest::Client::new()` (no timeout) and no hash check; the file is parsed by native whisper.cpp. Integrity rests on TLS and the upstream account. The Content-Length check added in Q2-12 has no test of its own (hyper already errors on a short body).
**Repro.** Code reading (`transcription/mod.rs`).
**Proposed fix.** Pin each model to a Hugging Face commit revision; verify a SHA-256 table before the rename; add connect and read timeouts; add a test for the length check.
**Source.** Security review S7.

## Q2-28 [medium, security, cut-list] Release pipeline: secrets to tag-pinned actions; updater unwired; `.asc` never released
**Problem.** `build.yml` passes `TAURI_SIGNING_PRIVATE_KEY`, Azure and Apple secrets to `tauri-apps/tauri-action@v0` in a job that also runs `dtolnay/rust-toolchain@stable` and `swatinem/rust-cache@v2` (tag-pinned). There is no `createUpdaterArtifacts`, nothing calls the updater, and the GPG `.asc` files are made after the release is published and only uploaded as workflow artifacts.
**Repro.** Code reading of `.github/workflows/build.yml` and `tauri.conf.json`.
**Proposed fix.** Pin release-job actions to commit SHAs; attach the `.asc` files with `gh release upload` (or sign before tauri-action); either set `createUpdaterArtifacts` and wire `check()`, or drop the updater per the cut-list ADR.
**Source.** Security review S8, QA.

## Q2-45 [medium, wrong-slide] .pro7 importer still drops blank, short and adjacent repeated slides
**Problem.** `importers/pro7.rs` scans the file for RTF text blocks, not the presentation's slide list. A blank ProPresenter slide has no text block, slides under 3 characters are dropped, and a block identical to the one before is folded. Voxxa's slide numbers then differ from ProPresenter's and `goto_slide(slide_in_song)` lands early.
**Repro.** A Pro7 presentation that starts with a blank slide: Voxxa's slide 0 is ProPresenter's slide 1.
**Proposed fix.** Parse slide boundaries from the protobuf, or compare the slide count with `current_state` and warn. Check against real .pro7 files from the founder.
**Source.** Both cross-reviews (10x nice 6, ponytail nice 11).

## Q2-46 [medium, wrong-slide] A refused or failed Blank is never retried
**Problem.** When the conductor emits Blank and the dispatch fails (Keystroke driver while Voxxa has focus, or a network error), the conductor already records the screen as blank. Nothing re-sends it when focus returns, so the lyrics stay up through the sermon.
**Repro.** Keystroke driver, Voxxa focused at the end of a song: Blank is refused with a toast; click PowerPoint: the lyrics stay.
**Proposed fix.** After a failed dispatch, sync the conductor's blank state from `Sent.blank`, or keep a pending Blank and retry it on the next tick.
**Source.** Ponytail cross-review (nice 9).

## Q2-47 [medium] The conductor blanks after two unmatched transcripts regardless of the configured time
**Problem.** Since Q2-02 the second unmatched transcript in a row blanks, whatever `unrecognized_speech_to_blank_secs` says. Two misheard sung lines in a row ("[Music]", "Thank you.", a garbled line) blank mid-song until the next matching line.
**Repro.** During a song, feed two transcripts that score under 70 against the song: Blank.
**Proposed fix.** Tune on real Whisper output of singing (founder check M3): ignore transcripts with fewer than 3 alphabetic words, and/or honour the configured time as a minimum.
**Source.** Verifier, ponytail cross-review (nice 6).

## Q2-48 [medium] ProPresenter REST: a presentation named shorter than the setlist title can never be shown
**Problem.** Since Q2-05, ProPresenter REST jumps to a new song only if the open presentation's name contains the setlist title (up to its first "("). If the presentation is named "Amazing Grace" and the setlist says "Amazing Grace My Chains Are Gone" (no brackets), every detection and every song-chip click blanks with "select …". It fails safe, but the song cannot be shown.
**Repro.** Fake or mock Pro7 REST with presentation "Amazing Grace"; setlist title "Amazing Grace My Chains Are Gone"; click the chip → blank and toast.
**Proposed fix.** Let the song chip confirm for every goto driver (as for FreeShow), and name the open presentation in the toast. Do not accept "either contains" (that is the "Grace" vs "Amazing Grace" wrong-slide path).
**Source.** Verifier, ponytail cross-review (should 3).

## Q2-31 [low, security] EasyWorship import: SQLite opened with `trusted_schema` on and defensive off
**Problem.** `importers/easyworship.rs` opens the untrusted copy with `SQLITE_OPEN_READ_ONLY | NO_MUTEX` only: `trusted_schema=1`, DEFENSIVE off, a WAL-mode library leaves `voxxa-ew6-*.db-shm`/`-wal` in %TEMP%, no size cap. No exploit path was found (identifiers allow-listed, read-only, no ATTACH).
**Repro.** Import a WAL-mode EW6 library; list `%TEMP%\voxxa-ew6-*`.
**Proposed fix.** Open `file:<tmp>?immutable=1` with `SQLITE_OPEN_URI`; `PRAGMA trusted_schema=OFF`; `SQLITE_DBCONFIG_DEFENSIVE`; cap the input size; delete the temp files.
**Source.** Security review S9, DBA note.

## Q2-32 [low, privacy] Outbound counter misses WS frames, redirects and mDNS; the privacy copy is wrong
**Problem.** Every reqwest `send()` is counted, but ProPresenter WS counts once per connect, redirect hops count once, mDNS is not counted, and the updater's own client is excluded. The privacy card says "all to apps you connected to", which is false after a model, Hymnary or Planning Center request.
**Repro.** Connect Pro7 WS and advance 10 slides: the counter rises by 1.
**Proposed fix.** Count each WS send and the mDNS browse; label it "HTTP requests and connections this session"; list Planning Center, Hymnary and Auto-detect in `index.html` and `main.js`.
**Source.** Security review S10, QA.

## Q2-33 [low, security] Presenter clients honour the system proxy; trace logging can capture the Pro7 WS password; whisper.cpp prints tokens
**Problem.** reqwest's system-proxy applies to the LAN presenter and discovery clients. At `RUST_LOG=trace`, tungstenite logs written frames including the Pro7 WS auth message, and the RingLogger has no target filter. whisper.cpp prints transcript tokens to stderr. At the default Info level no credential is logged (canary-tested).
**Repro.** `RUST_LOG=trace`, connect Pro7 WS with a password, generate a diagnostic report.
**Proposed fix.** `.no_proxy()` on presenter and discovery clients; cap non-`voxxa` targets at Info in `RingLogger::enabled`; install a whisper log callback that drops token output.
**Source.** Security review S11.

## Q2-49 [low] Resampler has no anti-alias filter
**Problem.** Capture at 48 kHz is linearly resampled to 16 kHz with no low-pass, so cymbals and sibilants above 8 kHz fold into the band Whisper hears.
**Repro.** Code reading (`audio/mod.rs` `Resampler`).
**Proposed fix.** Average each group of input samples (box filter) or a short FIR before decimating. Promote if founder check M1/M3 shows weak transcripts.
**Source.** Both cross-reviews.

## Q2-52 [low] Focus guard, stage no-activate and single instance are unverified on macOS and Linux
