## 1. FreeShow: what the source says (W1, index base, group ids, read-back, auth)

All paths below are in the FreeShow clone. Lines are from `c84386f3`.

**Transport and body (W1).** `src/electron/utils/api.ts:134-159`: the REST handler takes `req.body` whole as `data` (`:141`), accepts `?action=…&data={…}` as a fallback (`:143-149`), then `receivedData(data)` (`:151`). `receivedData` (`:256-271`) only reads `data.action`, assigns a `returnId` for `get_*` actions, and forwards the object unchanged to the renderer (`:263`). The renderer's `triggerAction(data)` (`src/frontend/components/actions/api.ts:448-462`) calls `API_ACTIONS[id](data)` with that same object; every handler reads its parameters at the top level: `index_select_slide: (data) => selectSlideByIndex(data)` reads `data.showId`, `data.layoutId`, `data.index` (`api.ts:245`, `apiHelper.ts:197-208`); `id_select_group: (data) => gotoGroup(data.id)` (`api.ts:247`). **So the wire format is `{"action":"index_select_slide","showId":…,"layoutId":…,"index":…}`.** Voxxa's driver sends `{"action":…,"data":{…}}` (`C:\dev\r2-review\src-tauri\src\presenters\freeshow.rs:47-49`), so `data.index` is `undefined`, `showRef[undefined]` is `undefined`, FreeShow shows a toast and returns (`apiHelper.ts:204-205`), and the REST layer still answers **204** because non-getters always do (`api.ts:152-156`). The likely origin of the nesting is the IPC type `src/types/IPC/ToMain.ts:77`, which declares a `data: any` field that the handlers never read. **Verdict: W1 confirmed; `goto_slide` has never worked; `next_slide`, `previous_slide`, `clear_slide`, `restore_output` take no fields and do work.** (measured)

**Index base.** `api.ts:453-454`: `// API start at 1, code start at 0` followed by `if (data.index !== undefined) data.index--`. This applies to every action with an `index` field (`index_select_slide`, `index_select_project_item`, `index_select_project`). Index `0` becomes `-1` and selects nothing (toast, 204). The stored output index is the decremented value (`apiHelper.ts:242-253`, `setOutput("slide", {id, layout, index: data.index, line: 0})`), and `get_output` returns that object as is (`src/frontend/components/actions/apiGet.ts:37-40`). **Command: 1-based. Read-back: 0-based.** (measured)

**Which show a jump targets.** Without `showId`, `selectSlideByIndex` uses `_show("active")` (`apiHelper.ts:200`): the show selected in the FreeShow *editor*, not the one on the output. If the operator clicks another song in the drawer, a bare `index_select_slide` jumps inside the wrong song. Voxxa must always send `showId` and `layoutId`, both of which `get_output` returns as `out.slide.id` and `out.slide.layout`. (measured)

**`id_select_group` semantics.** `gotoGroup(dataGroupId)` (`apiHelper.ts:68-91`) finds the current show from the output (`outSlide.id`, falling back to the active show), collects every slide whose `globalGroup === dataGroupId` where `dataGroupId` is a key of the global `groups` store, and calls `playNextGroup`. Default keys: `break, bridge, chorus, intro, outro, pre_chorus, tag, verse` (`src/electron/data/defaults.ts:5-14`); user-made groups get a uid. `playGroup` (`src/frontend/components/helpers/showActions.ts:622-661`) picks the first matching slide with `layoutIndex > outSlide.index`, else wraps to the first match; skips disabled slides; no-ops when the output is locked (`:623`) or already there (`:652`). So it is "next chorus from here, wrapping". Two verses share the key `verse`, so it cannot address verse 3. Planning Center and ChurchApps imports set `globalGroup: section.label.toLowerCase()` (`src/electron/contentProviders/planningCenter/request.ts:1102`, `…/churchApps/ChurchAppsShowBuilder.ts:84`), which yields keys like `verse 1` that are not in the default store, so `id_select_group` silently does nothing on those shows. `name_select_slide` fuzzy-matches group labels with `sortByClosestMatch` (`apiHelper.ts:210-240`): not deterministic enough for a follower. **Verdict: use `index_select_slide` as the only jump primitive; `id_select_group` is a Companion convenience, not a follower primitive.** (measured)

**Read-back.** A getter's reply is `{...request, data: <result>}` (`api.ts:461`, then `src/electron/utils/api.ts:274-280`), polled every 50 ms for up to 10 s (`:267`). `get_output` → `out` = `{slide: {id, layout, index, line}, background: {path…}, overlays…}` (`apiGet.ts:37-40`). Voxxa keeps `slide.id`, `slide.layout`, `slide.index` and drops the rest, as the binding's note already says. `get_output_group_name` returns the per-show group label string (`apiGet.ts:50-56`); **`get_output_slide_text` returns the lyrics (`apiGet.ts:42-48`) and voxxa must never call it** (ADR-007/011; it would put words into process memory and, through any log line, into the help bundle). Q12's plan to use `get_output_slide_text` for FreeShow read-back should change to `get_output`. (measured)

**Errors.** Unknown action → `console.error` in the renderer and 204 to the client (`api.ts:455`; `src/electron/utils/api.ts:152-156`). A locked output (`outLocked`) makes `index_select_slide` and `gotoGroup` no-ops (`apiHelper.ts:69`, `:243`). **There is no error channel for a failed select; read-back after every jump is the only way to know it happened.** (measured)

**Auth and binding.** `src/electron/utils/api.ts:17-38`: the password is optional; `checkAuth` is `!apiPassword || token === apiPassword`, so an unset password means every request is accepted. The token is read from `Authorization: Bearer …`, raw header keys (`authorization`, `x-api-key`), the query string (`?auth=`) and body fields (`auth`, `password`, `token`, `key`, `apiKey`, `authKey`) (`:20-36`). The REST server is `app.listen(PORT)` with no host (`:121`), the WebSocket server `http.createServer(app).listen(PORT)` (`:54-57`) with `cors: {origin: "*"}` (`:65`), and OSC binds `0.0.0.0` (`:198`). **All three listen on every interface.** 401 replies are JSON `{status: 401, error: "Unauthorized"}` (`:136`). (measured)

## 2. Architecture: the FreeShow driver (fire-then-verify)

**Shape (fits the codebase).** Keep `PresentationController` (`presenters/mod.rs:168-200`) and the one dispatch path (`dispatch.rs::drive`). Changes, all inside the presenters row (1,374 / 2,000; `freeshow.rs` is well under the 400 per-file cap):

1. **Wire format:** `send_action` builds `{"action": …, ...fields}`; no `data` key. One helper, one test.
2. **Jump:** `goto_slide(app_index)` sends `index_select_slide {showId, layoutId, index: app_index + 1}`. `showId` and `layoutId` come from the last `get_output` (cached on `connect`, refreshed by every verify). A song change goes through the binding's `goto.item` (`index_select_project_item {index}`, also 1-based), then the slide.
3. **Verify:** after any move, one `get_output` (within the binding's 750 ms); compare `(id, layout, index)`; on mismatch or timeout set ADR-025 § 2's `position_uncertain`, amber "FreeShow shows a different slide", send nothing automatic until the operator confirms. No automatic retry (ADR-025 § 6). `can_query_state: true`; `current_state()` fills `slide_index` (0-based) and a new `presentation_id: Option<String>` so `dispatch::presentation_is` can match the service plan's `{item.show_id}` instead of a name (names would need `get_show`, which returns slide text).
4. **Token:** `PresenterConfig.password` → `Authorization: Bearer` on every request, never in the URL or body; `connect` logs the base URL only (the existing `[FREESHOW] connected to {base}` line is fine). 401 → `CtlError::AuthRequired` (exists). **Open-API check:** on `connect`, probe once *without* the header; if FreeShow does not answer 401, the API has no password: red "FreeShow's API has no password; set one in Settings → Connections", refuse to connect unless `allow_open_api` is set (default off, FA-47). Voxxa only ever talks to `127.0.0.1`; a non-loopback host keeps ADR-025 § 6's amber warning.
5. **Never-call list** (compiled into the profile beside the existing write refusals): `get_output_slide_text`, `get_plain_text`, `get_show`, `get_slide`, `start_slide_recording`, `send_rest_command`, `emit_action`.
6. **Dispatch (wiring row, after V7):** `position_uncertain` (V8), the ADR-031 § 7 rule for stepping drivers ("any move that is not the next slide: log the target, send nothing, stop for the song"), and the verify hook. Perhaps 25 lines; they do not fit "everything else" today. (measured: 1 line left)

**Layout mapping, the design point the report misses.** A FreeShow layout for `v1 c v2 c` lists the chorus slides twice; voxxa's setlist from the `.txt` has each slide once. So voxxa slide → FreeShow layout index is many-to-one. Two ways out: (a) kit rule for v1: FreeShow shows for followed songs use **unique layouts** (every slide once; the parts map does the repeating) so `app_index = voxxa_slide` and `songcheck`'s `presenter_slides` count applies to FreeShow too; (b) a per-song resolver that reads the layout's slide-id list (`get_show_layout`; whether it carries text is **[UNVERIFIED]**) and picks the next occurrence after the current output index. Recommend (a) now, (b) with Q12's import later (FA-48). (opinion)

**Contract test (CI, no FreeShow, no model).** An in-process stub HTTP server (axum is already a dependency, `Cargo.toml:95`) that implements the *source-derived* contract: top-level fields, `index--`, 204 for non-getters and unknown actions, `{action, data}` for getters, 401 JSON when a password is configured and the header is missing, no-op when "locked". Named tests: `freeshow_goto_sends_top_level_fields_and_one_based_index`, `freeshow_readback_index_is_zero_based`, `freeshow_goto_verifies_and_flags_uncertain_on_mismatch`, `freeshow_goto_always_names_show_and_layout`, `freeshow_never_calls_text_getters`, `freeshow_token_only_in_authorization_header_and_never_logged` (capture the log sink), `freeshow_open_api_is_refused_by_default`, `freeshow_refused_actions_never_sent`. Then a founder-run recording against the real install fixes the stub (Q13's `--record-adapter`, or a 10-line PowerShell checklist whose output is ids and numbers only). The step is **UNVERIFIED live until that recording exists** (ADR-024 § 5), exactly as the binding says today.

**`kit/templates/bindings/freeshow.json` changes:** flatten every `json` body (remove `data` nesting where present; today the http steps are already flat, only the driver nests); `goto.item` uses `{app_slide1}` and a new 1-based `{item.project_item_index1}` (ADR-024 § 2 placeholder list grows by one); `goto` goes through `driver: goto_slide` with the show and layout from read-back; `readback.current` keeps `get_output` and gains `verify_after_move: true`; `transport.http.auth: "bearer"` gains `require_password: true`; the `note` is rewritten with the file:line facts above; `refused` gains the text getters.

**Presenter stays the universal fallback.** Nothing in `KeystrokeDriver`, the WorshipTools profile or `step_from` changes. The parts map emits a slide id; dispatch asks `capabilities().can_goto_slide`: FreeShow jumps and verifies; Presenter gets ADR-031 § 7's Right-only rule. One church profile field (`presenter.profile`) selects the path (ADR-024 § 1). (measured)

**Security, FreeShow surface.** Three listeners on every interface, optional password, `cors: *` on 5505 (a web page on the church Wi-Fi could drive FreeShow over socket.io if no password is set). Controls on the kit's FreeShow checklist: set the password; a Windows Defender Firewall inbound rule allowing 5505/5506 from `127.0.0.1` only (or the booth subnet if Companion runs elsewhere). Controls in voxxa: the open-API refusal above and a readiness item "FreeShow answers only on loopback" (a self-probe to the PC's own LAN address with std-only `UdpSocket::connect` + `local_addr()`; no packet, no new crate). Planning Center credentials inside FreeShow are FreeShow's; the kit's connector deny list still binds agents. (measured + opinion)

**Kill-switch path.** FreeShow's output lock turns every voxxa command into a no-op and the next read-back shows the mismatch, so voxxa holds itself. That is a panic path from any Companion surface, on any device, without opening voxxa's API beyond `127.0.0.1` (`http_api/mod.rs:4-9`, `:85-87`). Voxxa's own Pause stays a booth key or pedal (ADR-024 § 6). Do **not** widen the HTTP API binding for a stage button (FA-50). (measured + opinion)

## 4. The Listener DB (ADR-023, V12) as hindsight forced alignment

**Data model per song (schema v1 additions, all numbers):** on each `run`: `parts_order` (indices into `sections`, e.g. `[0,1,2,1,3,1]` as part instances), `detours` (counts by `(from_kind, to_kind)` and by `planned|unplanned`), `break_before_jump_ms` (gap before each off-plan move), `boundary_lag_ms` per part end (breath to first word), `leader` (an operator-chosen alias such as `L1`, never a name). Derived `plan` fields: `handicaps` per leader (ADR-031's four values, learned only when a leader has ≥ 3 confirmed runs, else defaults), `boundary` per leader (`words|plan`, ADR-031 § 4's option), `dwell_ms`, `max_gap_ms`. `heard` tokens stay as designed; everything stays in `<church_root>\practice\`, never in a help bundle or a tool's output (ADR-023 § 6). (opinion, consistent with ADR-023)

**What the follower consumes:** `plan.order` as the hint sequence (ADR-031 § 1), `handicaps` and `boundary` for that leader, `dwell_ms` as the pace prior (search width only; dead-reckoning never moves a labelled song), `max_gap_ms + 2 s` as the gap hold, `heard` as extra match tokens. Cold rules when missing, stale (`recog` mismatch) or `confidence < 0.6`.

**How `--learn` / `--confirm` feed it.** `--learn` is the parts map run *non-causally*: the same alignment and branch set with look-ahead over the whole session log, so a restarted song or an extra chorus needs no operator input. A model-based forced aligner (WhisperX, MMS_FA) is a later lab-only refinement for word timings, not needed for v1's order, dwell and detour statistics. `--learn` prints labels, counts and confidence; `--confirm` is unchanged; logic in the practice row (300), ≤ 20 voxxad lines (ADR-028 § 3). **Replay:** a run that read a practice file acts differently from a cold run, so the `start` line's `info` must carry the consumed `plan` (numbers), not a path; `info` is free JSON, no schema bump (measured: `events.rs:123-128`).
