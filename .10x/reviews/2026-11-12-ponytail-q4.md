# Ponytail lane — Q4 (2026-11-12 to 2026-11-13)

Independent pass, as the user asked (process rule, 2026-11-11). Q4 is a code step, so it ran the two-lane pattern used in Q1 to Q3:
- **Two build lanes** worked from the same base (a515d4d) in worktrees that could not see each other's code: the **10x lane** (`q4/10x`, `C:/dev/q4-10x`) and the **ponytail lane** (`q4/ponytail`, `C:/dev/q4-pony`, `ponytail` at level full).
- **Cross-reviews** of each lane.
- **Comparator:** read both diffs, picked the base, the grafts and the review fixes to apply.
- **Finisher:** merged the base into `q4/base` and applied the grafts and fixes, one commit each.
- **Adversarial verifiers:** re-ran every gate, ran Whisper Tiny on public-domain WAVs and mutated the code. Three rounds.

**Outcome:** base = **10x lane**, with three ponytail grafts and four review fixes. Verifier rounds 1 and 2 failed; each finding was fixed in new commits with a test that fails without the fix. **Round 3 passed**: two independent verifiers, both pass, at **a4bae0e** on `q4/base`. `q4/ponytail` (129d795) stays local for reference, not pushed.

All song text in this record is from the public-domain hymn Amazing Grace. The prayer is synthetic speech written for Q2.

## 1. The task, in short
Replace the recogniser closure and the 5 s speech batch in the shared loop (`listen::run`) with ADR-004's `Recognizer` trait: Whisper over a rolling 5 s window, decoded every 1 s (hop), with `single_segment`, token timestamps and `initial_prompt` biasing behind a `bias_enabled` flag. Feed every hypothesis to the conductor; keep the conductor API. Add a 10 s WAV test that checks monotonically increasing timestamps. Exit: hypotheses every second in the session log; conductor tests pass.

User decisions: one new budget row, "recognizer (transcription/ + recognizer code)", capped at 700 ("everything else" stays at 2,500); Q4 owns Q3-02 (#46, a pure and tested GUI event mapping); the PD session fixture may be re-recorded; no GUI change beyond the hop's cadence.

## 3. Cross-reviews

### Review of the 10x lane (a515d4d..a9c50a9)
The workflow returned no review result for this lane. The comparator read the 10x diff itself and found one gap: no loop-level test drives a wall clock through the lag gate, so nothing in CI tested the backpressure arithmetic in `listen::run`. That became graft 1 (§4).

### Review of the ponytail lane (a515d4d..129d795)
**Verdict: not ready to merge.** The seam was judged well built (exact stream-time arithmetic, deterministic 1 s hops at file speed, byte-identical replay, a pure and tested `to_gui`). The reviewer ran the conductor code unchanged in a simulation on idealised overlapping 5 s windows. Findings:
- **Must-fix 1, overlapping text:** each hop sent the whole 5 s window to the conductor, so its 40-word buffer held every word about five times. In the simulation It Is Well (V1 C V2 C V3 C) stopped at slide 1 or 3 and Amazing Grace's four verses at 2 words/s never left slide 0; the old batch got further. The real fixture showed the delay too (the line was heard at 15000, the goto came at 19000). Fix: stitch the overlapping hypotheses, hold new words until there are 4, add a multi-slide scripted test.
- **Must-fix 2, backpressure:** the stretch counted only `recognizer.feed` time, not conductor scoring or dispatch (measured `on_transcript` at 174 ms with 3 songs, 519 ms with 10, 2,642 ms with 50), so the backlog still grew without bound on a wall clock.
- **Should-fix 3:** the "second unmatched transcript blanks" rule was tuned for 5 s batches; at a 1 s hop it blanks after about 2 s, and overlapping windows count one shout-out several times. Make it time-based (`unrecognized_speech_to_blank_secs`).
- **Should-fix 4:** words were decoded token by token with lossy UTF-8, which garbles non-English text. Decode the segment text whole.
- **Should-fix 5:** release builds ran whisper.cpp about 3 times slower than debug (`opt-level = "s"` suspected); when the stretched hop exceeds 5 s, audio is dropped silently.
- **Should-fix 6:** ADR-014 missing; `loc_budget.py` cites it.
- **Nits:** zero-filling clips about 280 ms of a line's onset; a NUL in slide text would panic `set_initial_prompt`; the real-model test's 0.5 s tolerance and 276 s run time.

## 4. The comparator's ruling
**Base: the 10x lane at a9c50a9.** Both lanes met the gates and the exit demo. The 10x lane won on:
1. Bounded work: its lag gate counts everything in a loop pass (Whisper, scoring, detection rows, dispatch), so ponytail's must-fix 2 does not apply to it.
2. VAD gating that keeps the real audio (no clipped onsets).
3. Stricter timestamps and a stricter real-model test (at most 50 ms of backward jitter, a rise of at least 3 s, words inside [end − 5, end]).
4. A stronger GUI contract: exact payload bytes, `presenter_error()`, every action kind with `operator=false`.
5. ADR-014 written and Accepted before code.
6. The trait's required methods match the prompt literally; NUL already stripped.
7. A scripted overlapping-window test harness that the stitcher test could extend.

Costs of 10x: larger (recognizer row 374 against 311), a 330 KB WAV fixture and a `--bias` flag (kept: off by default, needed to measure ADR-004 E6).

Defects both lanes shared, to be fixed on the base: whole overlapping windows sent to the conductor, the count-based blank rule and per-token lossy UTF-8.

### Grafts and fixes applied by the finisher (`q4/base`, one commit each)
`q4/10x` merged with `--no-ff` (0d16b0e), then:
- **Graft 1** (b43151f): ponytail's slow-recogniser test, ported to the lag gate: `a_slow_recogniser_skips_hops_and_the_lag_stays_bounded`, with a 2.5 s fake decode on a wall clock and a variant that charges 700 ms per dispatched action (the case ponytail's own design missed).
- **Graft 2** (reported in the SDE record): hand mutation checks. Gate without the lag condition, gate without the VAD condition and `operator = true` in `gui_event` each fail at least one test.
- **Graft 3** (b4e9a28): a `shortcut:` comment at `set_initial_prompt` about the whisper-rs 0.13 CString leak.
- **Fix: stitcher** (0165be8, must-fix 1): `transcription::Stitcher` lines each hypothesis up against the words already heard, by text, with word times only breaking ties. The comparator's first option, padding short hops to 4 words, failed the new test (Amazing Grace at 2 words/s stopped after slide 1), so the fallback was used: new words are held until there are 4. Test: `stitched_hops_show_every_slide_once_in_order_at_any_singing_speed` (It Is Well V1 C V2 C V3 C and Amazing Grace's four verses at 2.0, 2.5 and 3.0 words/s); it fails with the stitcher bypassed.
- **Fix: UTF-8 words** (84c260d, should-fix 4): text from the segment, zipped with the token starts (`words_from_tokens`, unit-tested).
- **Fix: blank rule** (2bdd2b9, should-fix 3): blank when lyrics are showing and nothing has matched for 5 s; a 4.8 s shout-out does not blank.
- **Fixture** (68e403a) re-recorded; **ADR-014 note** (729a515); SDE record (4722786).
- **Release speed** (should-fix 5): `[profile.release.package.whisper-rs-sys] opt-level = 3` gave no gain and was not kept. The cause was found instead: on MSVC the `cmake` crate overwrites `CMAKE_C/CXX_FLAGS_RELEASE` with the `cc` flags minus every `/O` flag, so release builds compile whisper.cpp unoptimised. Setting those flags in the build environment measured 1.79-1.94 s per hop. Filed as ticket Q4-01.

## 5. Disagreements and how they were settled
1. **Backpressure:** skip hops on measured lag (10x) or stretch the hop to the feed time (ponytail). **10x**: it counts all work in a loop pass. Both are deterministic at file speed.
2. **VAD gating:** gate the decode (10x) or zero-fill silent hops (ponytail). **10x**: zero-filling clips onsets; ADR-014 lists and rejects it.
3. **Trait shape:** `Vec<Hypothesis>` plus `gate`, `end`, `error` (10x) or `anyhow::Result` (ponytail). **10x**: the required methods match the spec literally and the error line is kept.
4. **Overlap dedup:** neither lane had it. **Applied to the base** as the stitcher. The comparator asked for "pad to 4 words, else hold" and for clearing the stitch state when the gate closes on silence. Padding failed its test, so new words are held. Clearing on silence was later replaced in verifier round 2 (the words heard are kept across a pause shorter than 5 s).
5. **Blank rule:** 10x had accepted the faster blank as a risk; the review asked for a time-based rule. **Applied** (2bdd2b9), then extended in verifier round 2 by a tick rule (b2b8d0b).
6. **`#[ignore]` on the real-model test:** **not done** (above).
7. **`--bias` flag:** **kept** (10x only).
8. **10 s fixture:** **10x's** committed 10.3 s WAV.
9. **Word confidence:** mean token p (10x) or lowest (ponytail); nothing uses it yet. **10x's** kept.
10. **Payload serialisation:** **10x** (byte-exact `emit_str`); `serde_json::Value` would reorder keys.
11. **Review coverage:** only the ponytail lane had a review result; must-fix 1 and should-fixes 3-5 also applied to 10x and were carried over.
12. **The exit wording** (raised by verifier round 1): the finisher's ADR note restated "hypotheses every second" as "a hypothesis line every 1 to 2 s" without a user decision, and the measured gaps reached 3 s. **Settled by adding a `window` line** (9f666f1): one session-log line per decoded hop, every 1000 ms of speech at file speed, while the stitched `hypothesis` line stays the conductor's input. The restatement is marked superseded in ADR-014.
13. **"No conductor change"** (ADR-014 Decision 10): the finish made two blank and re-show fixes in the conductor (b2b8d0b, 613b894; 2bdd2b9 before them). **Accepted and recorded** in the ADR-014 notes as fixes, not tuning; the conductor API is unchanged.

## 6. Verifier rounds

### Round 1 (on the finish at 4722786): **fail**
- **Exit criterion not met:** the session log showed a stitched `hypothesis` line only every 1 to 3 s of speech (11 lines in 21.8 s of singing). Fixed by the `window` line (9f666f1).
- **Test gaps** (mutations that survived every gate):
  - E4c, E4, E5, E6: the GUI sink glue (negated `operator`, dropped `presenter-error`, dropped events). Fixed by `commands::gui_sink(event, emit, send)` with injected closures and 3 tests (10bc9b5).
  - F2: the backpressure floor (`caught_up`). Fixed by a device-stall test (63532bc).
  - D3, D4: `voxxad --bias` wiring and the loop's `bias()` call. Fixed by moving the flags to `bin/voxxad/cli.rs` and two tests (1a766f7).
- ADR-014 and the SDE record were corrected to the measured 1-3 s cadence (bafa0b4).
- Gates after the round: all 7 pass, 137 tests.

### Round 2 (on bafa0b4): **fail**, three failures in real Whisper Tiny runs
- **The prayer did not blank** after a 2-4 s pause: the stitched prayer transcripts spanned only 4 s, and the 5 s rule fired only on a transcript. Fixed by a tick rule in `Conductor::tick` (b2b8d0b): blank when lyrics are showing, a second unmatched transcript came, the first is 5 s old and the VAD still hears speech.
- **A re-shown slide after a pause** (gap2: a second goto 0/1 at 15000). Two causes:
  - The stitcher was cleared on silence, so the first window after the pause handed on the verse's last words again. A time cutoff (c288ef7) failed on the exit-demo re-run, because Whisper Tiny times a window's first word at the window start. It was replaced by 065b83f: the words heard are kept across a pause shorter than a window (5 s) and lined up by text.
  - A matched transcript in `inter_verse_silence` returned a goto to the slide still showing. It now returns `Noop` (613b894). This closes Q3-08 (#52) for that path.
- **Session-log `t` went backwards** after window and error lines (22 decreases in one run). Fixed in the recorder (fcd2934).
- Fixture re-recorded (85e57a5); `prayer.wav` added as a fixture; ADR-014 note and SDE record (a4bae0e).
- Gates after the round: all 7 pass, 142 tests.

### Round 3 (two independent verifiers at a4bae0e): **both pass**
- **Verifier A** (exit demo and behaviour): all 7 gates pass; 142 tests (55 unit + 87 integration).
  - Exit demo (debug, Whisper Tiny, file speed, 44.4 s service): `window` lines at 4000-8000, 10000-15000, 17000-26000 and 31000-38000 ms, every 1000 ms while the VAD hears speech; stitched `hypothesis` lines at 6000 8000 10000 11000 14000 18000 20000 23000 25000 32000 35000 36000. Actions: goto Amazing Grace/0 at 6000, goto Amazing Grace/1 at 25000, blank at 30600 (0.3 s into the prayer). Replay byte-identical on the action lines. Every line after the `start` line is byte-identical to the committed fixture; a second run is identical too.
  - Six other inputs (verses back to back, short gaps, each verse alone, the prayer alone, verse 2 then the prayer): no double advance, no slide shown twice, no goto during a prayer, `t` never decreasing, replay byte-identical.
  - 10 s real-model test passes; first-word starts [0.13, 0.12, 0.12, 0.12, 1.04, 2.03, 3.0, 4.0, 5.0].
  - Mock ProPresenter: nothing under `--shadow`; without it, version, slide_index, two triggers and a clear, matching the three actions.
  - Observations: the last lyric slide stays up for the first ~6.7 s of the 8.1 s prayer in 3 of 4 runs (known risk, ticket Q4-03). Under heavy load a `--realtime` run had decodes of 10-20 s; the bounded feeder (64 chunks) blocked and audio slipped, but work did not pile up; that run had no blank before the stop (ticket Q4-02). The "CI without a model" check could not be run as asked: pointing `APPDATA` elsewhere has no effect on Windows (ticket Q4-09); by reading, only the real-model test uses a model and it returns early without one.
- **Verifier B** (GUI contract and mutations): all 7 gates pass in a separate worktree (its "145 tests" is a miscount; its per-binary numbers add up to 142).
  - The GUI contract is unchanged apart from cadence: same event names, payloads, order and `operator=false`; `emit_str` is byte-identical to `emit` in tauri 2.12.5; `src/` untouched. The three conductor behaviour changes are all recorded in ADR-014.
  - 20 mutations killed (hop cadence, window trim, absolute times, log-before-apply, bias wiring, GUI names and payloads, backpressure, VAD gate, stitcher, hypothesis `t`, stop vs device loss).
  - Two low residuals, not blocking: the GUI glue closures (ticket Q4-08) and Rolling's word-time clamp, caught only by the local real-model test (ticket Q4-07).
