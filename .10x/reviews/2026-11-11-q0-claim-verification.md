**Missed by the notes (survived the skeptic):**

- **aligner: wrong-slide path:** After a song is committed, any non-empty transcript in InterVerseSilence or BlankHold (or after notify_external_blank) unblanks and re-shows the current slide without checking that the transcript matches that song. The only exits before this are a confident switch to another song after the dwell time, or a within-song advance. Speech after a song (announcements, sermon) brings the current lyric back. This is the opposite of 'a bad blank beats a wrong slide'. _(C:/dev/lamport/src-tauri/src/aligner/mod.rs:305-340 (the comment at :331 assumes a match that the code never checks); notify_external_blank :462-464, called from commands/mod.rs:756, http_api/mod.rs:212, tray/mod.rs:84)_
- **aligner: blanking semantics:** unrecognized_speech_to_blank_secs is used as a second silence timer, measured from last speech. BlankHold is reached only after silence, never on unrecognised speech, although the doc comment says otherwise. Any VAD speech refreshes last_speech, so talking mid-song never blanks. The machine never returns to Listening, because current_song is only ever set to Some. _(C:/dev/lamport/src-tauri/src/aligner/mod.rs:42 (doc), :229-261 (tick), :244-245; commands/mod.rs:303-310 (on_speech per VAD frame); the only assignment to current_song is aligner/mod.rs:427 (Some))_
- **aligner: no initial blank:** Conductor::new sets is_blank=true and state Listening, but tick() emits Blank in Listening only when !is_blank. Voxxa therefore never sends a Blank when listening starts, and whatever the presenter is showing stays on screen until the first Goto. 'Starts blank' is an assumption, not an action. _(C:/dev/lamport/src-tauri/src/aligner/mod.rs:155-156, 253-257)_
- **dispatch: global vs per-presentation index:** Goto passes the flat setlist global_index straight to drivers whose goto addresses a slide inside the currently active presentation: ProPresenter REST /v1/presentation/active/{index}/trigger, ProPresenter 7 WS presentationPath "0:0" / Pro6 "0", FreeShow index_select_slide, and OpenSong /presentation/slide/{index+1}. Unless the whole setlist is loaded as one presentation in the presenter, an absolute jump to any song after the first targets the wrong slide. The code has no per-song index translation. _(C:/dev/lamport/src-tauri/src/commands/mod.rs:443, 460, 475; aligner/mod.rs:441 (global = song_offsets + slide); propresenter7_rest.rs:199-204; propresenter7_ws.rs:231-249; freeshow.rs:162-167; opensong.rs:163-170)_
- **dispatch: toggle unblank:** The keystroke and OpenSong drivers implement unblank as the same toggle as blank. The dispatcher calls unblank for a delta-0 Goto, and for the first Goto (prev<0) on a driver without goto support, which includes keystroke. The conductor emits a delta-0 Goto when it recovers from InterVerseSilence while the output is still visible, so the screen is toggled to black and the conductor's is_blank is inverted. _(C:/dev/lamport/src-tauri/src/presenters/keystroke.rs:183-186; opensong.rs:156-160; commands/mod.rs:454-467; aligner/mod.rs:333-338)_
- **dispatch: capability gating:** Blank and Unblank are not gated on can_blank. On ProPresenter 7.0-7.8/6 WS (can_blank false, no blank/unblank override) every conductor Blank fails as Unsupported and is only logged. The conductor marks itself blank while the audience still sees the lyric, and a delta-0 Goto (unblank) also fails. A failed Goto logs and returns early without telling the conductor, so the conductor's position and the presenter's diverge. _(C:/dev/lamport/src-tauri/src/commands/mod.rs:415-434, 494-497; propresenter7_ws.rs:132-138 (no blank/unblank impl in :217-249); presenters/mod.rs:160-165)_
- **presenters: open-loop control:** Presenter state is never read back to verify an action. The dispatcher relies on last_dispatched_global and next/prev deltas, so any operator action inside the presentation app causes silent drift. current_state is used in only two places: get_presenter_state, a Tauri command that is registered but never invoked by the GUI, and internally by the ProPresenter REST unblank. _(C:/dev/lamport/src-tauri/src/commands/mod.rs:441-498 (last_dispatched), 1041-1051 (get_presenter_state); lib.rs:126 (registered); src/main.js has no get_presenter_state invoke (only get_presenter_info at :1136); propresenter7_rest.rs:190)_
