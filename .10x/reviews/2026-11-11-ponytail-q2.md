# Ponytail lane — Q2 (2026-11-11)

Independent pass, as the user asked (process rule, 2026-11-11). Q2 has a verification half and a fix half, so it ran both patterns:
- **Verification:** a QA lane and a Security lane each tested 1568810 on their own; the ponytail audit of Q0 (items 1–20) was the checklist they re-confirmed; a triage step merged the findings; a skeptic (refutation pass) tried to knock down each contested item.
- **Fixes:** the agreed fix-now set was implemented twice, in worktrees that could not see each other: the **10x lane** (`q2/10x`) and the **ponytail lane** (`q2/ponytail`, `ponytail` full). Each lane was then reviewed by the other discipline, as in Q1: `ponytail-review` on the 10x lane, a 10x Senior Engineer review on the ponytail lane. A comparator picked the base and the grafts, a finisher applied them, and an adversarial verifier re-ran every gate and mutated every fix.

**Outcome:** base = **10x lane**, with ponytail grafts. Verifier round 1 failed on one pre-existing wrong-slide defect (Q2-44); the orchestrator fixed it with a test (b09373d) and re-ran the gates. Q2 code head: **b09373d** on `q2/10x`. The `q2/ponytail` branch stays local for reference (head 0d3162f), not pushed.

## 7. Linux and macOS risks carried to CI

- `tauri-plugin-single-instance` pulls zbus (D-Bus) on Linux: +32 lock packages, first compiled on CI.
- The stage no-activate path is Windows-only; `focusable: false` on macOS/Linux and `is_focused()` semantics are unverified (ticket Q2-52).
- `tests/model_download.rs` uses local TCP servers and timing; a CI runner with a proxy that does not bypass localhost, or a very slow runner, could make it flaky.
- `tests/importer_slides.rs` relies on pdf-extract 0.12.1 panicking on the two fixtures and on `.gitattributes` keeping the PDFs binary.
- Audio defaults on CoreAudio and ALSA/Pulse are untested; a device offering only U8 or I32 now fails with a clear error.
