# Real-time lyrics-to-audio alignment and live lyrics following (arXiv cs/eess, 2019 to Nov 2026)

Scope note: this file covers lyrics-specific alignment and tracking. Pure score following (audio-to-score) is covered in a sibling file (arxiv_score_following.md) and is only cited here where it is the sole source for a structure-handling technique. No song lyrics are quoted anywhere in these notes; songs are referred to by title only. Numbers are reported exactly as the source gives them; "AAE" = average absolute error, "PCO" = percentage of correct onsets within a tolerance (0.3 s unless stated), "MedAE" = median absolute error.

Research-method note: arXiv full-text search was run for "lyrics alignment", "lyrics-to-audio alignment", "real-time lyrics alignment", "lyrics transcription whisper", "lyrics timestamps singing", "forced alignment singing", "opera tracking real-time", and "score following". Papers were then read via arXiv HTML / ar5iv. Two non-arXiv primary sources (ISMIR 2021 user study, DAFx 2025 paper, Interspeech 2025 paper) were read from publisher PDFs because they directly answer the tolerance and CTC questions.

---

## Key Question 1: Which arXiv papers address lyrics alignment or lyric tracking in real time / online (not just offline forced alignment)?

### Takeaway
Only a handful of arXiv papers do genuinely online lyrics tracking, and all of them are from the classical/opera domain: Brazier & Widmer (ISMIR 2021, arXiv 2107.14496) and Park, Yong, Kwon & Nam (ICASSP 2024, arXiv 2401.09200), plus Brazier & Widmer's related opera-tracking papers (2006.11033, 2010.11013, 2105.08531, 2110.02592). Both lyrics-tracking systems avoid aligning live audio directly to text; they pre-align lyrics to a *reference recording* offline and then run on-line time warping (OLTW) between live audio and the reference, with the acoustic model producing phoneme posteriors. Best online numbers are roughly 0.35 to 0.85 s mean error with 75 to 92 % of onsets within 1 s, far worse than offline pop-music aligners (0.15 to 0.25 s mean). No arXiv paper was found that does online lyric tracking of polyphonic pop/worship music directly from lyric text without a reference recording.

### Cited Findings

**Park, Yong, Kwon, Nam, "A Real-Time Lyrics Alignment System Using Chroma And Phonetic Features For Classical Vocal Performance", ICASSP 2024, arXiv:2401.09200**
- Goal is to take live singing audio and output the current lyric position for applications such as automatic subtitling of concerts or operas; the stated constraints are that the system can only use past input and must keep latency minimal. — [arXiv abs](https://arxiv.org/abs/2401.09200)
- Two-phase design: an offline phase pre-aligns the reference recording to a MIDI-synthesised score (lyrics and note timings from MusicXML, using chroma + DLNCO features with memory-restricted multi-scale DTW via synctoolbox); an online phase aligns live target audio to the reference with Dixon-style OLTW (linear time complexity), 16 kHz, 25 frames per second, OLTW window 3 s, audio enqueued in 160 ms chunks. Lyrics are never aligned to audio directly. — [arXiv HTML](https://arxiv.org/html/2401.09200)
- Acoustic model: CRNN on a 66-bin log-mel spectrogram (hop 640, FFT 1280) with a *unidirectional* LSTM (1024 units) producing a phonetic posteriorgram (PPG); trained on TIMIT (speech, not singing) with collapsed label sets Phoneme39, Viseme14, Phoneme5. — [arXiv HTML](https://arxiv.org/html/2401.09200)
- Dataset: the authors recast the Schubert Winterreise Dataset as "winterreise_rt" (performance HU33 as reference, SC06 as target, MIDI-rendered score; 24 songs, voice-note level) because no public benchmark for real-time lyrics alignment existed. — [arXiv HTML](https://arxiv.org/html/2401.09200); dataset script [github.com/laurenceyoon/winterreise_rt](https://github.com/laurenceyoon/winterreise_rt)
- Results (Table 1, exact): Offline Chroma & DLNCO: AAE 302 ms, MedAE 137 ms, PCO <300 ms 83.35 %, <500 ms 93.31 %, <1000 ms 98.1 %. Online Chroma only: AAE 1,366 ms, MedAE 1,098 ms, PCO<300 69.42 %. Online Mel spectrogram: AAE 1,222 ms, PCO<300 75.75 %. Online Phoneme39 alone: AAE 2,637 ms (worst). Online Chroma + Phoneme5 (best): AAE 376 ms, MedAE 136 ms, std 630 ms, PCO <200 ms 64.75 %, <300 ms 75.49 %, <500 ms 85.82 %, <1000 ms 92.26 %. — [arXiv HTML](https://arxiv.org/html/2401.09200)
- No measured latency, runtime or hardware figures are reported; only the 160 ms buffer and the linear-complexity OLTW claim. — [arXiv HTML](https://arxiv.org/html/2401.09200)
- Main failure case: prolonged silence followed by a sudden voice onset (illustrated on the song "Frühlingstraum"); phonetic features help recover. Chroma alone "did not work well for singing". Acknowledged limitation: the acoustic model is trained only on speech so it is not robust to polyphonic singing with accompaniment (future work). — [arXiv HTML](https://arxiv.org/html/2401.09200)
- Code: [github.com/laurenceyoon/real-time-lyrics-alignment](https://github.com/laurenceyoon/real-time-lyrics-alignment), licence CC-BY-NC 4.0, conda environment, usage is an evaluation notebook (no live-microphone script documented on the README page). Companion site: [laurenceyoon.github.io/real-time-lyrics-alignment](https://laurenceyoon.github.io/real-time-lyrics-alignment/)

**Brazier & Widmer, "On-Line Audio-to-Lyrics Alignment Based on a Reference Performance", ISMIR 2021, arXiv:2107.14496**
- Acoustic model: CP-ResNet (time receptive field 57 frames) on 80 MFCCs (16 kHz, 20 ms window, 10 ms hop) outputting a 60-dim vector every 40 ms (57 phonemes from the union of English/German/French/Spanish/Italian + space + instrumental token + CTC blank); trained with CTC on DALI 1.0 original *mixtures* (no vocal extraction), 20 s windows. Two models: "5lang" (4,027 songs, 259.4 h) and "english" (3,257 songs, 210.8 h). — [ar5iv](https://ar5iv.labs.arxiv.org/html/2107.14496)
- Alignment: OLTW between the live posteriogram and a pre-computed reference-performance posteriogram (window of 8,000 reference vectors, about 320 s, cosine distance, blank frames skipped); lyrics are linked to the reference by manual annotation, so no text-to-phoneme tool is needed at run time. — [ar5iv](https://ar5iv.labs.arxiv.org/html/2107.14496)
- Theoretical latency 280 ms (from the 280 ms future context of the acoustic model); the authors explicitly do not measure runtimes. Acoustic models with long receptive fields (>1.5 s) are stated to be unsuitable for real time. — [ar5iv](https://ar5iv.labs.arxiv.org/html/2107.14496); [ISMIR PDF](https://archives.ismir.net/ismir2021/paper/000007.pdf)
- Results (mean absolute tracking error / % annotations within 1 s): Don Giovanni Fischer 2018: baseline features 1,915 ms / 66.1 %; 5lang 846 ms / 80.5 %; english 818 ms / 80.5 %. Manacorda 2019: 5lang 824 ms / 77.6 %; english 963 ms / 76.1 %. Jingju (Beijing opera, a cappella, out-of-training-language): 5lang 964 ms / 87.5 %; english 810 ms / 89.0 % vs baseline 2,943 ms / 61.5 %. — [ar5iv](https://ar5iv.labs.arxiv.org/html/2107.14496)
- An Italian-only model (10.8 h training data) diverged on all alignments. Structural differences between versions are left as future work. No code or model release is stated. — [ar5iv](https://ar5iv.labs.arxiv.org/html/2107.14496)

**Brazier & Widmer, "Improving Real-time Score Following in Opera by Combining Music with Lyrics Tracking", arXiv:2110.02592 (2021)**
- A music (orchestral) tracker leads; the lyrics tracker is switched in when the position enters a voice-dominated part (parts labelled by a voice-over-music ratio computed on the reference) and switched out at music-dominated parts. Music tracker steps every 10 ms; lyrics tracker outputs every 40 ms with about 280 ms (28 frames) delay; compensating that delay with an offset did *not* help. — [ar5iv](https://ar5iv.labs.arxiv.org/html/2110.02592)
- Results (bar level, Don Giovanni): Fischer: music baseline 811 ms mean / 91.8 % ≤1 s; prior SOTA "musicP" 373 ms / 93.4 %; combined M&L 335 ms / 94.1 % ≤1 s, 97.3 % ≤2 s, 99.2 % ≤5 s. Manacorda: baseline 561 ms / 90.1 %; M&L 410 ms / 91.6 %. — [ar5iv](https://ar5iv.labs.arxiv.org/html/2110.02592)

**Brazier & Widmer, "Towards Reliable Real-time Opera Tracking: Combining Alignment with Audio Event Detectors to Increase Robustness", arXiv:2006.11033 (2020)**
- Baseline OLTW on a full live opera: Act 1 mean error 9.6 s (std 19.1 s), 74 % of bars ≤1 s, max 72.7 s; Act 2 mean 14.0 s, only 40 % ≤1 s. Causes: applause treated as music, silence/stage noise, unwritten interludes, recitatives, structural mismatch. With applause/pause/speech detectors: Act 1 mean 0.3 s, 94 % ≤1 s; Act 2 mean 1.4 s, 89 % ≤1 s (max still 61.5 s). — [ar5iv](https://ar5iv.labs.arxiv.org/html/2006.11033)
- Detector rules: applause >400 ms while within 1 s of a scene transition → halt and jump to the transition; neither speech nor music for >400 ms near a transition → halt and jump; if the reference has voice within 4 s after a transition, halt until live voice activity appears. Classifiers are 1-layer 55-cell LSTMs (~1.1 s context) trained on ~15 h of annotated YouTube classical recordings. Search window 40 s of reference. — [ar5iv](https://ar5iv.labs.arxiv.org/html/2006.11033)

**Brazier & Widmer, "Addressing the Recitative Problem in Real-time Opera Tracking", arXiv:2010.11013 (FRSM 2020)**: two parallel trackers (music-sensitive and speech-sensitive features) combined via pre-trained music/speech classifiers; no numbers in the abstract. — [arXiv search listing](https://arxiv.org/search/?query=real-time+lyrics+alignment&searchtype=all)

**Other fast-but-offline systems (not online)**
- HCLAS-X (Kang et al., arXiv:2307.04377, 2023): hierarchical sentence-then-word aligner using a cross-correlation matrix between IPA text and separated-vocal mel features; deployed in music streaming services; ~4.8 s per song on an RTX 3090 (text preprocessing 2.64 s, audio preprocessing 1.33 s, sentence model 0.74 s, word model 0.11 s). Not claimed to run online. — [ar5iv](https://ar5iv.labs.arxiv.org/html/2307.04377)
- WhisperMSS (Liang et al., Interspeech 2025, not arXiv): Mandarin *a cappella* singing transcription + syllable segmentation; motivates CTC+attention because "attention-based methods like Whisper have efficiency and alignment issues in real-time use"; reports AAE 0.02 s and onset F1 92.3 % at a 0.02 s tolerance on clean Mandarin a cappella. — [ISCA PDF](https://www.isca-archive.org/interspeech_2025/liang25c_interspeech.pdf)

**Patent (non-academic, for awareness only)**: USPTO 12444393 / 12620379 describe synchronising a prerecorded vocal backing track to a live vocal performance, time-stretching when alignment confidence drops, processing in roughly 30 ms or less. — [USPTO](https://image-ppubs.uspto.gov/dirsearch-public/print/downloadPdf/12444393)

### Inferences
- Both published real-time lyric trackers chose audio-to-*reference-audio* OLTW rather than audio-to-text, because a reference performance carries pronunciation and timing and avoids text-to-phoneme errors; for a church with its own recordings of each song, this "reference performance" approach is directly reproducible (a prior Sunday's recording becomes the reference).
- Causality matters: Park's acoustic model uses a unidirectional LSTM (streamable); Brazier's CP-ResNet needs 280 ms of future context; the offline pop aligners (Huang 2022, Wang 2023, HCLAS-X) use bidirectional recurrent layers and so cannot be streamed without a lookahead buffer.
- The online-vs-offline gap in Park's own table (AAE 376 ms online vs 302 ms offline on the same data, but PCO<300 drops from 83 % to 75 %) is a reasonable estimate of the price of going online with OLTW, before any polyphonic-accompaniment penalty.

### Gaps
- No arXiv paper evaluates online lyric tracking on polyphonic pop, contemporary worship, hymns, or congregational singing. All online evidence is classical lieder, opera, and Jingju.
- Neither online system reports wall-clock latency or hardware; only design parameters (160 ms buffer, 280 ms model context, 40 ms output stride).
- No reports of these systems being run on consumer GPUs.

## Key Question 2: Which methods use CTC / Whisper / wav2vec-style acoustic models for lyrics alignment, and what accuracy did they reach on polyphonic and a cappella singing?

### Takeaway
The offline state of the art on the standard polyphonic English benchmark (JamendoLyrics, 20 songs) has moved from mean 0.82 s (Stoller 2019, CTC character model) to about 0.15 to 0.23 s mean / 92 to 94 % PCO at 0.3 s (Durand 2023 contrastive; Gupta 2020 Kaldi genre-informed; Huang 2022 CTC phoneme+pitch MTL), with medians around 0.04 to 0.05 s. A cappella / clean solo singing is far easier (mean 0.13 s on Hansen solo with a Kaldi model; 0.023 s character MAE on Opencpop with Whisper-based alignment; 0.02 s AAE on Mandarin a cappella). Whisper's native timestamps are too unreliable for lyric timing (0.82 s MAE vs 0.071 s for a CTC head on the same Whisper encoder), so every Whisper-based aligner bolts a CTC/forced-alignment head onto the encoder or uses a separate wav2vec2 phoneme aligner (WhisperX pattern).

### Cited Findings

**Benchmarks and datasets**
- DALI (Meseguer-Brocal, Cohen-Hadria, Peeters, ISMIR 2018; arXiv:1906.10606): 5,358 audio tracks with time-aligned vocal melody notes and lyrics at four granularity levels, built from karaoke-game user annotations plus a teacher-student singing-voice-detector loop; Zenodo DOI 10.5281/zenodo.1492443. — [arXiv abs](https://arxiv.org/abs/1906.10606)
- JamendoLyrics (Stoller et al. 2019): originally 20 English songs with word-level timings; the extended multi-language version now has 80 songs with word and line annotations plus metadata flags LyricOverlap, Polyphonic, NonLexical; the GitHub repo is archived (read-only since 30 April 2025) and the dataset moved to Hugging Face (huggingface.co/datasets/jamendolyrics/jamendolyrics). — [github.com/f90/jamendolyrics](https://github.com/f90/jamendolyrics)
- Jam-ALT (Cífka et al., arXiv:2311.13987 / 2408.06370): 79 songs in English, French, Spanish, German with revised, formatting-aware full-song transcripts; dataset + metrics at [audioshake.github.io/jam-alt](https://audioshake.github.io/jam-alt/). — [arXiv HTML](https://arxiv.org/html/2311.13987); [arXiv HTML](https://arxiv.org/html/2408.06370v1)
- MIREX tolerance window for lyrics alignment is 0.3 s. — [ISMIR 2021 PDF](https://archives.ismir.net/ismir2021/paper/000052.pdf)

**CTC character model (end-to-end, polyphonic, weakly supervised)**
- Stoller, Durand, Ewert, ICASSP 2019, arXiv:1902.06797: Wave-U-Net predicting characters directly from raw polyphonic audio, CTC loss trained from weak *line-level* timings only, 44,232 internal songs; ~20 character distributions per second. Mauch: mean AE 0.35 s, Perc 77.2 %; Jamendo: 0.82 s, 70.4 % (median did not increase, so the mean is outlier-driven). Adding a vocal separator: Jamendo 0.38 s / 76.8 %, Mauch 0.27 s / 78.1 %. MIREX 2017 systems on Mauch were 9.03 to 22.23 s mean. Largest outliers on Hip-Hop and Metal ("likely due to slurred pronunciation"). No model code; only the Jamendo dataset. — [ar5iv](https://ar5iv.labs.arxiv.org/html/1902.06797)

**Kaldi HMM/TDNN-F phoneme models (NUS, MIREX winners)**
- Gupta et al. ICASSP 2019, arXiv:1906.10369: TDNN-F trained on ~50 h DAMP solo singing, adapted with 70 DALI polyphonic songs. *A cappella* (Hansen solo): mean AE 0.13 s, 94.1 % correct with extra OpenSMILE features (0.20 s baseline). *Polyphonic* without vocal extraction: Hansen-poly mean 0.93 s (median 0.15 s), Mauch-poly mean 1.93 s (median 0.18 s). Comparison table: MIREX 2017 AK 7.34 / 9.03 s, GD 10.57 / 11.64 s; MIREX 2018 CW 2.07 / 4.13 s (Hansen-poly / Mauch-poly). Error analysis: long instrumental interludes in Mauch drive boundary errors. — [ar5iv](https://ar5iv.labs.arxiv.org/html/1906.10369)
- Gupta, Yılmaz, Li, ICASSP 2020, arXiv:1909.10200: Kaldi TDNN-F trained on 3,913 polyphonic DALI tracks (no vocal extraction) with genre-informed silence/phone models (pop, hiphop, metal). Mean word-boundary error: Mauch 0.21 s, Hansen 0.18 s, Jamendo 0.22 s. Training on extracted vocals instead was far worse (Mauch 3.62 s). Transcription WER polyphonic 54 to 67 %; with a lyrics-only language model 44 to 60 %. — [ar5iv](https://ar5iv.labs.arxiv.org/html/1909.10200)
- NUS reported first place in both MIREX 2020 lyrics-to-audio alignment and lyrics transcription (announced ISMIR 2020, 16 Oct 2020), two years running for alignment; the system is AutoLyrixAlign (web demo autolyrixalign.hltnus.org). — [NUS news](https://cde.nus.edu.sg/ece/news/aligning-lyrics-to-singing-vocal-top-results-in-the-mirex-international-benchmarking-2020/)
- Demirel, Ahlbäck, Dixon, ICASSP 2021, arXiv:2102.09202 ("low resource"): vocal separation + energy VAD + lyrics-only 20-gram LM + anchor words + segmented forced alignment. Jamendo: mean 0.31 s (Demucs) / 0.38 s (Spleeter), median 0.05 s, PCS(0.3 s) 0.93 / 0.90. RAM 343 MB mean (max 748 MB) vs 13,740 MB for the NUS GC1 system. Comparison rows: SD1 0.82 / 0.10 / 0.85; SD2 0.39 / 0.10 / 0.87; VA 0.37 / n.a. / 0.92; GC1 0.22 / 0.05 / 0.94 (mean / median / PCS). Code: [github.com/emirdemirel/ASA_ICASSP2021](https://github.com/emirdemirel/ASA_ICASSP2021). — [ar5iv](https://ar5iv.labs.arxiv.org/html/2102.09202)

**CTC phoneme models with multi-task pitch (DALI-trained, code released)**
- Huang, Benetos, Ewert, ICASSP 2022, arXiv:2202.01646: separated vocals → 128-bin mel → conv + residual + 3 BiLSTM(256) → phoneme (41 classes, CTC) and pitch (47 classes, frame CE, λ=0.5); Viterbi forced alignment; a separate boundary-detection model (BDR) adds line-start probabilities to the Viterbi score to cut cross-line errors. Trained on DALI v2 English (4,224 train / 1,056 val). Word level AAE / PCO: Jamendo baseline 0.31 / 0.94, MTL 0.23 / 0.94, MTL+BDR 0.23 / 0.94; Mauch MTL+BDR 0.20 / 0.91. Line level Jamendo MTL+BDR 0.25 / 0.94. Prior work in their table: SDE2 0.39 / 0.87, GC 0.22 / 0.94, VHM 0.37 / 0.92 (Jamendo). — [ar5iv](https://ar5iv.labs.arxiv.org/html/2202.01646)
- Code: [github.com/jhuang448/LyricsAlignment-MTL](https://github.com/jhuang448/LyricsAlignment-MTL), MIT licence, checkpoints referenced (Baseline, MTL, BDR), requires pre-separated vocals (Spleeter / Open-Unmix suggested); author notes a multilingual successor "performs better" and recommends it. — [GitHub](https://github.com/jhuang448/LyricsAlignment-MTL)

**Contrastive (non-CTC) alignment, smallest model, best Jamendo numbers**
- Durand, Stoller, Ewert, ICASSP 2023, arXiv:2306.07744: audio encoder (10 residual conv blocks, 5 s spectrogram at 11,025 Hz, 930 ms receptive field, 64-dim embeddings) + text encoder with symbol context window; trained on 87,785 professional songs (EN/ES/DE/FR); model ~1.2 M parameters (4.8 MB). Decoding: monotonic path over the similarity matrix plus a line-based mask with 2.5 s tolerance at line borders. Jamendo EN: M6 character model AAE 0.15 s / PCO 92 %; M5 phoneme 0.16 s / 93 %. Their CTC baseline M1 got 0.90 s (0.20 s only when given the similarity model's mask). Removing line-based decoding raises AAE 0.15 → 0.24 s. Multi-language (JamendoLyrics Multi-Lang), language-conditioned: AAE 0.18 s / PCO 94 % overall. Comparison table (Jamendo EN): SDE 0.82 / 85; VHMRA 0.37 / 92; DAD 0.31 / 93; HBE 0.23 / 94; GYL 0.22 / 94. — [arXiv HTML](https://arxiv.org/html/2306.07744v1)
- Stated error causes: last words of a line placed at the start of the next line and vice versa; phoneme models inherit G2P errors; individual symbols confused with instrumental sections; CTC cannot handle missing or extra symbols and needs one-to-one text-audio matching except for temporal distortion; a strong autoregressive language model objective *hurt* alignment. Only the dataset annotations are released, no model code or weights stated. — [arXiv HTML](https://arxiv.org/html/2306.07744v1)
- Kick, Grötschla, Lanzendörfer, Wattenhofer, "Contrastive Lyrics Alignment with a Timestamp-Informed Loss", NeurIPS 2024 Audio Imagination workshop: a "box loss" that uses timestamps directly, cleaned DALI, and a JamendoLyrics++ evaluation set with more genre diversity; no numbers on the public page; OpenReview id peM113bm8Z. — [NeurIPS page](https://neurips.cc/virtual/2024/105750)

**Industrial cross-correlation model**
- HCLAS-X (Kang et al. 2023, arXiv:2307.04377): trained on ~67,000 in-house Korean/English songs with sentence start times (HX-IH) or DALI (HX-D). Jamendo: HX-IH MAE 0.16 s, MedAE 0.043 s, Perc 89.0 %, Mauch0.3 0.93, Mauch0.2 0.91; HX-D (DALI only) MAE 0.42 s, MedAE 0.043 s. Comparison rows: ST 0.38 / 0.097; VA 0.37; GU 0.22 / 0.050; EM 0.31 / 0.050 (MAE / MedAE). Confidence-based QA: ~91 % of words within ±0.2 s; thresholding confidence at 0.08 gives F1 95.17 % for flagging bad alignments. No code. — [ar5iv](https://ar5iv.labs.arxiv.org/html/2307.04377)

**CTC autoencoder with frame-wise masked CE (2025)**
- Cheng, Nakano, Goto, "Improving Lyrics-to-Audio Alignment Using Frame-wise Phoneme Labels with Masked Cross Entropy Loss", DAFx 2025 (not on arXiv): autoencoder trained with CTC + reconstruction loss, plus partial frame-wise phoneme labels derived from word-level annotations and a masked CE loss. Jamendo test: MAE 0.216 s ("comparable" to SOTA), MedAE 0.041 s ("top"). No code listed. — [DAFx archive](https://dafx.de/paper-archive/details/o-wYFu7sQFE_GuYrAHxIHA); [PDF at AIST](https://staff.aist.go.jp/m.goto/PAPER/DAFX2025cheng.pdf)

**Whisper-based alignment**
- Wang, Leong, Lin, Su, Jang, "Adapting pretrained speech model for Mandarin lyrics transcription and alignment", arXiv:2311.12488 (2023): Whisper-medium encoder + an "align RNN" (2-layer BiGRU 384) predicting 401 pinyin syllables + silence, trained with CTC + CE (multitask with ALT), Viterbi forced alignment at inference, HT-Demucs vocals in, accompaniment augmentation at 0/-5/-10 dB SNR. Character-level MAE: MIR-1k mixture 0.0709 s; Opencpop clean solo 0.0228 s; Whisper's own timestamp decoder on MIR-1k: 0.822 s (0.412 s when songs are cut to ~7 s). Ablations: w/o CTC 0.131 s; w/o augmentation 0.099 s; mixture without separation 0.098 s; Spleeter 0.123 s. Authors chose a CTC head because Whisper's discrete timestamp tokens are "less robust". Annotations at [github.com/navi0105/LyricAlignment](https://github.com/navi0105/LyricAlignment) (model weights not stated as released). — [ar5iv](https://ar5iv.labs.arxiv.org/html/2311.12488)
- Phonsa (inside MPEcho, arXiv:2607.26698, 2026): Whisper-based phoneme aligner extending Wang et al. 2023, replacing the RNN with chunked self-attention (4 heads, 500-frame = 10 s chunks, 50 % overlap) and adding boundary and breath tokens; CTC + weighted frame CE; trained on M4Singer + Opencpop (30.9 h), tested on GTSinger (16.5 h): MAE 32.6 ms vs MFA 233.9 ms; PCO at ±0.1 s 0.965 vs 0.767. Whether it is causal/streaming is not stated. Code and weights are said to be at the MPEcho project page (lonian6.github.io/MPEcho.github.io). — [arXiv HTML](https://arxiv.org/html/2607.26698)
- SongTrans (Wu et al., arXiv:2409.14619, 2024): fine-tuned Whisper-v3-1.5B generates lyrics plus word durations as text; word-duration MAE ~0.108 s on M4Singer; lyric WER 10.81 % vs Whisper baseline 32.56 %; no code, no speed. — [arXiv HTML](https://arxiv.org/html/2409.14619)
- WhisperX (Bain et al., arXiv:2303.00747): Whisper transcribes VAD-cut ~30 s chunks, then a wav2vec2 phoneme CTC model (default BASE_960H) force-aligns the transcript with DTW over logits. Whisper's attention-derived word timestamps scored 78.9 precision / 52.1 recall (AMI, 200 ms collar) vs WhisperX 84.1 / 60.3; Whisper buffered decoding drifts because timestamp errors accumulate across windows. Alignment adds <10 % overhead; batched VAD chunks give ~12× speed-up on an A40. Code: [github.com/m-bain/whisperX](https://github.com/m-bain/whisperX). — [ar5iv](https://ar5iv.labs.arxiv.org/html/2303.00747)
- Rousso et al., "Tradition or Innovation: A Comparison of Modern ASR Methods for Forced Alignment", arXiv:2406.19363 (speech, not singing): word boundaries within 100 ms on TIMIT: MFA 97.4 %, MMS (wav2vec2 CTC) 94.7 %, WhisperX 94.2 %; within 50 ms: 89.4 / 75.7 / 82.4 %. Median word error: MFA 12.5 ms, MMS 29.3 ms, WhisperX 23.5 ms. Unfiltered WhisperX mean on Buckeye ~11,685 ms due to drift on long inputs. CTC's lack of pre-aligned training data is blamed for looser timing. — [ar5iv](https://ar5iv.labs.arxiv.org/html/2406.19363)

**Lyrics transcription accuracy (WER) with Whisper / wav2vec2 — the recogniser Voxxa currently depends on**
- Ou, Gu, Wang, ISMIR 2022, arXiv:2207.09747 (wav2vec2 transfer, Demucs vocals, hybrid CTC/attention): WER Jamendo 33.13 %, Hansen 18.71 %, Mauch 28.48 %, DSing test 12.99 %, DALI test 30.85 % (vs TDNN-F 76.37 % Jamendo; MSTRE-Net 34.94 %). Code: [github.com/guxm2021/ALT_SpeechBrain](https://github.com/guxm2021/ALT_SpeechBrain). — [ar5iv](https://ar5iv.labs.arxiv.org/html/2207.09747)
- LyricWhiz (Zhuo et al., ISMIR 2023, arXiv:2306.17103): Whisper-large multiple runs + GPT-4 selection; WER Jamendo 24.25 %, Hansen 7.85 %, DSing 13.78 %; MUSDB18 mixture ~47 to 51 %, vocals 25 to 33 %. Whisper failure modes: unrelated text (music descriptions, watermarks, ads), "Thank you." on instrumental sections, run-to-run variance from temperature sampling; dropping lines with no-speech probability >0.9 helps. Code + MulJam dataset (CC BY-NC-SA): [github.com/zhuole1025/LyricWhiz](https://github.com/zhuole1025/LyricWhiz). — [arXiv HTML](https://arxiv.org/html/2306.17103)
- Jam-ALT results (all languages, WER %): Whisper large-v2 37.8, +language hint 27.9, +Demucs 44.5; Whisper large-v3 35.5, +lang 32.6, +Demucs 48.0; OWSM v3.1 69.3; LyricWhiz (EN only) 24.6; AudioShake v3 (proprietary) 16.1. Findings: Whisper often picks the wrong language on separated vocals; v3 is not consistently better than v2 on lyrics; backing vocals are "susceptible to being omitted". — [arXiv HTML](https://arxiv.org/html/2408.06370v1); [arXiv HTML](https://arxiv.org/html/2311.13987)
- Syed, Meresman Higgs, Cífka, Sandler, arXiv:2506.15514 (2025): Whisper large-v2 without fine-tuning; Jam-ALT short-form WER 20.99 % (mix) vs 21.08 % (mdx_extra vocals); MUSDB-ALT 23.59 % mix, 20.00 % separated, 14.19 % true vocal stem; long-form native 23.02 % → 20.35 % with a separated-vocals RMS-VAD segmenter. Separation artifacts can trigger hallucinations; segment boundaries that cut through vocal activity cause hallucinations; Whisper deletes non-lexical vocables and backing vocals even on stems. Code: [github.com/jaza-syed/mss-alt](https://github.com/jaza-syed/mss-alt). — [arXiv HTML](https://arxiv.org/html/2506.15514)
- Huang, Sousa, Demirel, Benetos, Gadelha, arXiv:2506.02339 (Interspeech 2025): LoRA fine-tune of Whisper large-v2 with a mixture/vocals consistency loss; overall mixture WER 32.36 % vs raw Whisper 35.42 % on 118 songs (Multi-Lang Jamendo + IT/PT); no latency measured; annotations at [github.com/weAreMusicAI/alt-datasets-interspeech2025](https://github.com/weAreMusicAI/alt-datasets-interspeech2025). — [arXiv HTML](https://arxiv.org/html/2506.02339v1)
- HeartTranscriptor (HeartMuLa, arXiv:2601.10547, 2026): fully fine-tuned Whisper-Medium on ~100,000 verified songs (~7,000 h, Demucs vocals, pseudo-labelled by Whisper-Medium and WER-filtered); SSLD-200 English WER 0.2816 vs Whisper-Medium 0.4695 and SongPrep 0.3460; internal bench 200en 0.1873. No timestamps/alignment mentioned; repo [github.com/HeartMuLa/heartlib](https://github.com/HeartMuLa/heartlib), transcriptor release terms not stated in the paper text read. — [arXiv HTML](https://arxiv.org/html/2601.10547)
- Other 2025–2026 Whisper lyric work: Greek ALT two-stage Whisper Large-v3 adaptation 27.2 % WER (arXiv:2609.11302); VietLyrics 647 h + fine-tuned Whisper (arXiv:2510.22295); VocalParse LALM joint lyrics/melody/word-note (arXiv:2605.04613, code github.com/pymaster17/VocalParse, no numbers in abstract); KunSet Kunqu opera syllable alignment corpus (arXiv:2610.29031). — [arXiv search](https://arxiv.org/search/?query=lyrics-to-audio+alignment&searchtype=all); [VocalParse abs](https://arxiv.org/abs/2605.04613)

**Generic CTC alignment tooling relevant to lyrics**
- CTC-segmentation (Kürzinger et al. 2020, arXiv:2007.09127): aligns given utterance texts to long audio from CTC posteriors with a windowed DP (O(M) memory); the transcript start may align anywhere so preambles do not break it; per-segment confidence (min of mean frame probabilities) lets low-scoring utterances be discarded (threshold 0.22 used). TED-LIUM: 0.31 s mean, 88.8 % within 0.5 s (Gentle 0.41 s / 82.0 %; Aeneas 9.01 s); robust to 10–30 s of random speech added at the ends. Code: [github.com/cornerfarmer/ctc_segmentation](https://github.com/cornerfarmer/ctc_segmentation). — [ar5iv](https://ar5iv.labs.arxiv.org/html/2007.09127)
- torchaudio MMS_FA bundle (wav2vec2 trained on 23,000 h / 1,100+ languages) exposes `forced_align()` / `merge_tokens()` and a `<star>` token dimension (enabled by default, `with_star=False` to disable); the tutorial page read does not state the star token's purpose. — [torchaudio tutorial](https://docs.pytorch.org/audio/stable/tutorials/forced_alignment_for_multilingual_data_tutorial.html)

### Inferences
- Polyphonic pop word-onset accuracy of ~0.15–0.25 s mean / ~0.04–0.05 s median is attainable *offline* with small models (Durand's 1.2 M-parameter net; Huang's CRNN), i.e. compute is not the barrier — causality and the look-ahead needed by DTW/Viterbi are.
- Whisper's native timestamps (0.4–0.8 s MAE in singing, drift on long audio) are roughly the size of Voxxa's reported 1–3 s timing error contributors; every paper that needed sub-200 ms lyric timing replaced them with a CTC/forced-alignment head, which is the single clearest technical lesson for Voxxa.
- Training on *mixtures* (Gupta 2020, Brazier 2021) or with accompaniment augmentation (Wang 2023) consistently beat relying on a vocal separator at inference; separators add latency and artifacts that provoke Whisper hallucination.

### Gaps
- No MIREX 2020–2024 official per-system result tables could be retrieved (the MIREX wiki returned an expired TLS certificate); numbers above come from the papers' own comparison tables, which use differing Jamendo splits/protocols.
- Durand 2023 (best Jamendo result) has no released code or weights; HCLAS-X and Cheng 2025 likewise.
- No arXiv paper reports alignment accuracy on hymns, worship music, or choir/congregation singing.

## Key Question 3: Which methods handle structure (repeated sections, jumps, skipped parts, improvised repeats), and how do they decide a jump happened without moving early?

### Takeaway
No lyrics-alignment paper on arXiv models out-of-order or repeated sections explicitly; CTC and monotonic DTW decoders assume the text is sung once in order. The only rigorous treatments are in real-time score following: Nakamura et al.'s HMM with factorised stop/resume jump probabilities and an explicit silent "break" state (arXiv 1512.07748), and Brazier & Widmer's two-tracker scheme (arXiv 2105.08531) in which a high-resolution tracker may only jump at known part boundaries while a coarse full-score tracker proposes jumps and is trusted only when its own trajectory has had a plausible tempo slope (0.5–1.5) over the last ~9 s. Both report that similar-sounding repeated sections (choruses) and short stretches between jumps cause the remaining failures, and both trade a lower jump prior for fewer false jumps.

### Cited Findings
- Nakamura, Nakamura, Sagayama, "Real-Time Audio-to-Score Alignment of Music Performances Containing Errors and Arbitrary Repeats and Skips", IEEE/ACM TASLP 2015, arXiv:1512.07748: two-level HMM (one top state per score event, sub-events for sustain/pause); repeats and skips allowed between *any* two events; jump probability factorised into a per-origin "stop" probability and per-destination "resume" probability so all jumps cost O(score length) instead of O(N²). A second model inserts an explicit silent "break" state so a repeat/skip is a two-step transition through silence, motivated by practice data in which 59 of 63 jumps had breaks longer than 500 ms. — [ar5iv](https://ar5iv.labs.arxiv.org/html/1512.07748)
- False-jump control in that model is via the stop probability alone: larger values made the follower misdetect ordinary insertion/deletion/substitution errors as repeats or skips; the break model produced ~1.2× fewer misdetections than the no-break model at stop probabilities ≥1e-10. No pruning is used so the follower can reacquire position after being lost. Catch-up after a repeat/skip averaged about 0.7 s on clarinet data; detected 56 of 63 real jumps (Antescofo: 4); synthetic jumps detected 13/13, 11/11, 11/12, 10/10. Real time up to ~1,000 events on a 3.3 GHz i3 with pause states (hop 20 ms). Most misses: similar sections (e.g. choruses) and performances under 5 s between jumps; monophonic input only. — [ar5iv](https://ar5iv.labs.arxiv.org/html/1512.07748)
- Brazier & Widmer, "Handling Structural Mismatches in Real-time Opera Tracking", arXiv:2105.08531 (2021): high-resolution "Jump OLTW" (JOLTW) over MFCCs (10 ms hop, ~40 s window) permits jumps only at known part boundaries, limited to 8 transitions (repeat current part, continue, or jump to one of the next 6 parts); a low-resolution tracker (600 ms Hann window, 300 ms hop, last 30 distance vectors, diagonal matching with jumps anywhere) proposes positions. Reliability factor rf = 1 only if the LR position advanced by 15–45 low-res frames over each 30-frame span (slope 0.5–1.5, i.e. plausible tempo); the HR tracker is reset to the LR position *only* when rf = 1 and the HR position lies outside the LR interval; after reset the HR cost matrix is seeded from LR costs and all else set to +∞. — [ar5iv](https://ar5iv.labs.arxiv.org/html/2105.08531)
- Results on 20 simulated versions of Don Giovanni (33–66 % of parts removed, one part repeated after applause): baseline 10.4 % part-wise / 7.2 % bar-wise correct; JOLTW alone 28.3 / 17.3 %; JOLTW+LR 84.0 % part-wise, 51.2 % bar-wise, 66.0 % within 5 bars; LR alone when rf = 1: 98.9 % part-wise (rf = 1 covers 63.5 % of the opera). Authors say the best model is "still not acceptable" for subtitling; recitatives, interludes before recitatives, and noisy JOLTW hypotheses at part transitions are the weak points; backward jumps other than repetitions were not tested. — [ar5iv](https://ar5iv.labs.arxiv.org/html/2105.08531)
- Brazier & Widmer 2020 (arXiv:2006.11033) handle *pauses* between sections by halting the tracker and jumping to the next transition when applause (>400 ms) or no music/speech (>400 ms) is detected within 1 s of a transition, and by waiting for live voice activity if the reference has voice within 4 s after the transition. — [ar5iv](https://ar5iv.labs.arxiv.org/html/2006.11033)
- Lyrics-alignment decoders assume in-order text: Durand et al. note CTC "cannot handle missing or extra symbols well" and needs one-to-one text-audio matching except for temporal distortion; their fix is a line-based mask that keeps a line's words together with a 2.5 s tolerance at line borders (removing it raises AAE from 0.15 to 0.24 s). — [arXiv HTML](https://arxiv.org/html/2306.07744v1)
- Huang et al. 2022 add a line-boundary detector whose probabilities are added to the Viterbi score to reduce cross-line errors (line-level Jamendo AAE 0.30 → 0.25 s). — [ar5iv](https://ar5iv.labs.arxiv.org/html/2202.01646)
- HCLAS-X aligns hierarchically (whole-song sentence level first, then words within sentence segments) and exposes a confidence score; at confidence threshold 0.08 the maximum F1 for flagging misaligned words is 95.17 % with 98.57 % recall. — [ar5iv](https://ar5iv.labs.arxiv.org/html/2307.04377)
- CTC-segmentation tolerates text that is not in the audio (and audio not in the text) by allowing the transcript start anywhere and scoring each segment's confidence; it is penalised "even when only a single word is missing from a long utterance". — [ar5iv](https://ar5iv.labs.arxiv.org/html/2007.09127)
- JamendoLyrics metadata flags "LyricOverlap" (overlapping vocal lines) and "NonLexical" per song, acknowledging these as distinct difficulty classes. — [github.com/f90/jamendolyrics](https://github.com/f90/jamendolyrics)
- Wav2Karaoke (Ngo et al., ANLP 2026, non-arXiv) reports that end-to-end karaoke-style note+lyric alignment performance is "substantially lower than may be expected from isolated benchmarks" when forced aligner (MFA) and pitch tracker are cascaded; syllable-level alignment is required because one word may span several notes. — [ANLP PDF](https://www.anlp.jp/proceedings/annual_meeting/2026/pdf_dir/C2-17.pdf); code [github.com/NyokoKei/Wav2Karaoke](https://github.com/NyokoKei/Wav2Karaoke)

### Inferences
- Translating the two score-following designs to lyric slides: (a) keep a fine tracker that may only jump at slide/section boundaries (JOLTW's "repeat current, continue, or next k"), and (b) require a coarse, independent estimate to agree *and* to have shown a sane tempo slope for several seconds before accepting a jump; this is exactly the "don't move early" gate Voxxa lacks.
- Nakamura's "break state" is a cheap, strong prior for worship: section repeats and skipped verses almost always follow a musical gap or instrumental turnaround, so a jump should cost much less right after detected silence/instrumental than mid-phrase.
- Repeated choruses defeat acoustic-only jump detection (both papers); for identical lyric lines the only disambiguators are the planned order (prior), elapsed time, and musical cues (chord/chroma), which argues for combining a lyric follower with chroma-level section matching as Park et al. did.

### Gaps
- No arXiv paper measures how quickly or how reliably a *lyrics* tracker recovers after an unplanned repeat or skipped verse.
- No published rule for hysteresis/dwell time before committing a jump beyond Brazier's slope gate and Nakamura's stop probability; values would have to be tuned on Voxxa's own service recordings.

## Key Question 4: What tolerances and latencies are reported as achievable, and what causes errors?

### Takeaway
The field's standard tolerance is 0.3 s (MIREX), and the one perceptual study (ISMIR 2021, Deezer) found karaoke users detect lyrics *lagging* audio at about +0.22 s but tolerate lyrics *ahead* of audio until about -0.33 s; slow tempo and high word rate widen the ahead-tolerance further. Offline SOTA sits within that window for ~92–94 % of words; online systems reach ~75 % within 0.3 s and ~92 % within 1 s. Reported pipeline latencies are 160–280 ms of buffering/model context plus 40 ms output stride; the dominant error sources are instrumental interludes and silence-to-onset transitions, line-border confusion, separation artifacts, Whisper hallucination/drift, and acoustically similar repeated sections.

### Cited Findings
**Tolerances**
- Masclef, Vaglio, Moussallam, "User-centered evaluation of lyrics-to-audio alignment", ISMIR 2021: MIREX fixed the error tolerance at 0.3 s with no psychology experiment behind it. In a karaoke-style experiment (80 songs across pop/rock/rap/metal, several languages; 2,458 annotations from 193 participants), the 50 %-detection thresholds were -0.33 s for lyrics *ahead* of audio and +0.22 s for lyrics *lagging*; positive (lagging) offsets are more easily detected; thresholds were asymmetric for 72 % of individuals; proportions at -0.3 s vs +0.3 s differ significantly (χ² = 4.26, p = .038) while -0.3 s vs +0.2 s do not. — [ISMIR PDF](https://archives.ismir.net/ismir2021/paper/000052.pdf)
- Same study: the 50 % threshold for lyrics-ahead is -0.36 s for slow tempo (93 BPM quartile) vs -0.31 s for fast (138 BPM), and -0.39 s for high words-per-second vs -0.28 s for low; a word misaligned *on the beat* raised confidence in the "asynchronous" judgement (mean 4.1 vs 3.5 for last word, p < 0.006). They propose an asymmetric PCO window [-0.3, +0.2] s and a smooth "Perceptual-PCO". — [ISMIR PDF](https://archives.ismir.net/ismir2021/paper/000052.pdf); [Deezer summary](https://newsroom-deezer.com/2021/11/user-centered-evaluation-of-lyrics-to-audio-alignment/)
- Achieved offline (polyphonic Jamendo): 92–94 % of word onsets within 0.3 s, mean 0.15–0.23 s (Durand 2023, Gupta 2020, Huang 2022). — [arXiv HTML](https://arxiv.org/html/2306.07744v1)
- Achieved online (classical, reference-based): 75.49 % within 0.3 s, 85.82 % within 0.5 s, 92.26 % within 1 s, AAE 376 ms (Park 2024); 76–89 % within 1 s, mean 0.8–0.96 s (Brazier 2021 lyrics tracker alone); 91.6–94.1 % of bars within 1 s, mean 335–410 ms (Brazier 2021 music+lyrics). — [arXiv HTML](https://arxiv.org/html/2401.09200); [ar5iv](https://ar5iv.labs.arxiv.org/html/2107.14496); [ar5iv](https://ar5iv.labs.arxiv.org/html/2110.02592)

**Latencies**
- Park 2024: 160 ms audio buffer, 3 s OLTW window, 25 fps features; runtime not measured. — [arXiv HTML](https://arxiv.org/html/2401.09200)
- Brazier 2021: 280 ms theoretical latency from acoustic-model future context; 40 ms output stride; runtime not measured; models with >1.5 s receptive field deemed unsuitable for real time. — [ar5iv](https://ar5iv.labs.arxiv.org/html/2107.14496)
- Nakamura 2015: 20 ms hop; ~0.7 s average catch-up after a repeat/skip; real time for up to ~1,000 (with pause states) or ~10,000 (without) score events on a 3.3 GHz i3. — [ar5iv](https://ar5iv.labs.arxiv.org/html/1512.07748)
- Brazier 2020 detectors: 400 ms of applause/pause before the tracker halts; 1.1 s classifier context. — [ar5iv](https://ar5iv.labs.arxiv.org/html/2006.11033)
- HCLAS-X offline: 4.8 s per full song on an RTX 3090. — [ar5iv](https://ar5iv.labs.arxiv.org/html/2307.04377)
- WhisperX: alignment adds <10 % to Whisper's runtime; Whisper itself processes 30 s windows. — [ar5iv](https://ar5iv.labs.arxiv.org/html/2303.00747)

**Error causes reported**
- Prolonged silence followed by sudden vocal onset (Park 2024). — [arXiv HTML](https://arxiv.org/html/2401.09200)
- Long instrumental interludes drive word-boundary errors (Mauch set vs Hansen set); error distributions are heavy-tailed: many boundaries near zero error plus some far off (Gupta 2019). — [ar5iv](https://ar5iv.labs.arxiv.org/html/1906.10369)
- Hip-hop and metal songs with slurred pronunciation produce the largest outliers (Stoller 2019). — [ar5iv](https://ar5iv.labs.arxiv.org/html/1902.06797)
- Line-border confusion (last words of a line attached to the next line); single symbols confused with instrumental sections; G2P errors in phoneme models (Durand 2023). — [arXiv HTML](https://arxiv.org/html/2306.07744v1)
- Source-separation artifacts and residual accompaniment; weaker separators (Spleeter) can be worse than the raw mixture; Whisper "complete hallucination" appending unrelated text (Wang 2023). — [ar5iv](https://ar5iv.labs.arxiv.org/html/2311.12488)
- Whisper picks the wrong language on separated vocals; backing vocals omitted; low-intelligibility singing (Jam-ALT). — [arXiv HTML](https://arxiv.org/html/2408.06370v1)
- Segment boundaries cutting through vocal activity trigger Whisper hallucinations; Whisper deletes non-lexical vocables and backing vocals even on clean stems (Syed 2025). — [arXiv HTML](https://arxiv.org/html/2506.15514)
- Whisper timestamp drift across buffered windows (WhisperX; Rousso 2024 unfiltered mean ~11.7 s on long Buckeye inputs). — [ar5iv](https://ar5iv.labs.arxiv.org/html/2303.00747); [ar5iv](https://ar5iv.labs.arxiv.org/html/2406.19363)
- Singing-specific acoustic differences listed in the 2024 survey "More than words" (arXiv:2403.09298): larger pitch fluctuation, vowel elongation/shortening to fit rhythm (more variation for vowels), larger loudness variability, altered pronunciation, different vocabulary, harmonic/percussive interference, and vocal-activity detection failing on instrumental solos. Melisma, repeated phrases, reverb and congregational singing are *not* discussed. — [arXiv HTML](https://arxiv.org/html/2403.09298)
- Singing-specific lexicon modification for elongated vowels improved word boundaries in an Interspeech 2018 NUS paper (secondary source via search snippet; not read in full). — [NUS PDF](https://smcnus.comp.nus.edu.sg/archive/pdf/2017-2018/2018_Chitralekha_Interspeech.pdf)
- Acoustically similar sections (choruses) and <5 s between jumps cause missed jump detections (Nakamura 2015); recitatives whose acoustics differ between performances defeat coarse matching (Brazier 2021). — [ar5iv](https://ar5iv.labs.arxiv.org/html/1512.07748); [ar5iv](https://ar5iv.labs.arxiv.org/html/2105.08531)
- Whisper's "+Demucs" degrades WER for every Whisper variant except large-v2 on English (Jam-ALT), so separation is not a free robustness fix. — [arXiv HTML](https://arxiv.org/html/2408.06370v1)

### Inferences
- The perceptual asymmetry (ahead tolerated to ~-0.33 s, lag detected at ~+0.22 s) means a slide follower should bias toward firing slightly *early* (within ~0.3 s) rather than late; Voxxa's "occasional early moves" of 1–3 s are far outside that window, but a sub-300 ms early bias would be perceptually free.
- Voxxa's 1–3 s errors are consistent with the known ~0.4–0.8 s Whisper timestamp error plus 30 s-window buffering and the ~0.5 s pass interval, rather than with the limits of the acoustic evidence (online OLTW reached 0.38 s AAE on live-style classical input).
- Phrase-onset detection after silence is exactly the condition Park et al. identify as the hardest for OLTW, so onset-gated slide changes will be most fragile at verse starts after instrumental turnarounds.

### Gaps
- No arXiv paper quantifies error vs reverberation time, microphone distance, or congregation/choir unison singing; no live-worship or hymn dataset exists in the surveyed literature.
- No measured end-to-end latency (audio-in to position-out) for any online lyrics tracker.
- Melisma-specific error rates were only found in a Greek-language thesis surfaced by search (not read, not arXiv), so no reliable figure can be given.

- A GTX 960 (Maxwell, 2–4 GB) is not benchmarked anywhere in this literature; however the aligner networks involved (Park's CRNN PPG net at 25 fps; Huang's CRNN; wav2vec2-base in WhisperX at ~49 frames/s) are one to two orders of magnitude cheaper per second of audio than Whisper Small, which Voxxa already runs at ~0.5 s per pass on that GPU, so a phoneme-posterior + OLTW follower updating every 160–200 ms is plausible on the same hardware. This is an inference, not a measured result.
- The cleanest reproducible path with public code is: Park-style OLTW against a reference recording of each song (code CC-BY-NC, acoustic model would need retraining on singing/DALI for polyphonic robustness) or Huang-style CTC phoneme posteriors (MIT) fed to a causal windowed Viterbi/CTC-segmentation decoder with Nakamura/Brazier-style jump gating.
- Licensing: Park's code is non-commercial, AutoLyrixAlign is GPLv3, MulJam is CC BY-NC-SA; Huang's MIT code and torchaudio/WhisperX are the permissively licensed options.
